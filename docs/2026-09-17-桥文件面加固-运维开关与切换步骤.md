# 桥文件面加固 · 运维开关与切换步骤

> 日期：2026-09-17 ｜ 对应 spec：`docs/superpowers/specs/2026-09-17-bridge-fs-hardening-and-arch-cleanup-design.md` §10
> 适用：P0-1（路径闸门）、P0-2（/raw-file 限额）、P0-4（外壳 CSP）

本文件是**运维手册**：改哪个环境变量、何时切、怎么验证、怎么回滚。所有开关都遵循
「**默认保守 + 单开关回滚**」——出问题只需把变量改回即可，不需要改代码。

## 1. 开关总表

| 变量 | 默认 | 作用 | 影响面 / 风险 |
|---|---|---|---|
| `YFW_FS_GUARD` | 读=warn、写=enforce | 闸门级别：`off` / `warn` / `enforce` | `off` = 完全回到加固前行为（应急回滚）；`warn` 只记日志不拦；`enforce` 按 roots 拒绝 |
| `YFW_FS_ROOTS` | 空 | **读**允许根（`;` 或 `,` 分隔） | 为空时读侧不做允许校验（仅 deny 列表生效） |
| `YFW_FS_WRITE_ROOTS` | 空 | **写**允许根 | 为空时写侧只做 deny 过滤（允许根外普通路径**仍可写**——见 §4 已知取舍） |
| `YFW_FS_DENY_ROOTS` | 空 | 额外**拒绝**根（写侧硬闸门） | 与内置清单取并集；在 `warn` 级别下**同样拦** |
| `YFW_FS_DENY_PATHS` | 空 | 额外**拒绝的具体文件**（读写都拒） | 用于凭据文件；在 `warn` 级别下**同样拦** |
| `YFW_RAW_FILE_MAX_BYTES` | `33554432`（32MB） | `/raw-file` 单文件上限 | 超限返回 413（不再回吐内容） |
| `YFW_CSP_MODE` | `report` | 外壳 CSP 模式：`off` / `report` / `enforce` | `report` 只上报违规不阻断；`enforce` 才真正拦截 |

内置的拒绝根（无需配置即生效，写侧）：数据根（`~/.yfw`、`~/.yfworking`）、`~/.ssh`、`~/.aws`、
`~/.docker`、`~/.kube`、`~/.config`、`~/.gitconfig`、`~/.npmrc`、各 shell rc（`.bashrc`/`.zshrc`/`.profile` 等）、
系统目录（`%SystemRoot%`、`Program Files`、`%PROGRAMDATA%`）、`%APPDATA%` 与启动项。
内置的凭据文件（读写都拒）：`<数据根>/settings.json`、`<数据根>/auth.json`。

## 2. CSP 切换步骤（本项要求「先观察一天再切」）

### 阶段 A —— 观察（当前状态，默认即此）

1. 确认模式：不设 `YFW_CSP_MODE`（或显式设为 `report`）。
2. 正常使用一天，覆盖这些路径以免漏判：
   - 打开/保存文件、目录选择、Office（docx/xlsx）预览与转换
   - HTML 文件预览（`FileEditor` 的 HtmlPreview）
   - 应用智控（驾驶舱）、浏览器自动化、企微会话、知识库
3. 查看违规上报：CSP 违规会出现在渲染层 DevTools Console
   （`Content-Security-Policy-Report-Only` 的 `securitypolicyviolation`）。
   **判定标准**：只允许出现"预览载荷内部"的违规（如技能模板加载 CDN），
   不应出现**外壳自身**的 `script-src` 违规（那意味着某些模块/内联脚本会被 enforce 打死）。

### 阶段 B —— 切 enforce

1. 设置 `YFW_CSP_MODE=enforce` 并重启应用。
2. **必做回归**（这四类是最可能被打断的）：
   - [ ] 应用能起来、界面渲染正常、控制台无 `script-src` 违规
   - [ ] 桥连通：能列目录/读文件/写文件（说明 `connect-src` 正确放行了 51517 的 HTTP+WS）
   - [ ] 预览可用：HTML 预览能显示、Office 预览能显示、PDF 能显示
   - [ ] 驾驶舱可用（`frame-src` 放行了桥与 `file:`）
3. 若任一项失败 → **立即把 `YFW_CSP_MODE` 改回 `report`**（无需改代码），并记录被打断的指令。

### 阶段 C —— 收紧（可选，仅在 b 全绿后）

`electron/csp-policy.cjs` 的 `SHELL_CSP_DIRECTIVES` 里，`script-src`/`style-src` 含 `file:`
是为兼容打包态 `file://` 外壳（file URL 在 Chromium 下是 opaque origin，`'self'` 未必匹配）。
**在打包产物上**试着去掉 `file:` 跑一遍阶段 B 的回归；全绿则可去掉，CSP 强度随之提高。

### 明确无法去除的一项

`style-src 'unsafe-inline'` **必须保留**：CodeMirror 的 `style-mod` 在 document 上挂载时走
`createElement('style')` + `textContent`（`node_modules/style-mod/src/style-mod.js:100/135`），CM6 不传 nonce。
其风险远低于 `script-src 'unsafe-inline'`（后者本策略已禁止）。

## 2.5 高危判定改版（2026-09-17 fix-A）——本次唯一会改变你**日常观感**的改动

`shared/high-risk.mjs` 改为三级分类（T1 既问也标 / T2 标而不问 / T3 都不标），
并确立不变量 **`sign ⊇ approval`**（approval 认定的高危必须也标高危）。

**你会看到的变化**（都是刻意的）：

- **弹窗里的"高危"标识更可信**：此前 `curl … | sh`（远程代码执行）、`shutdown`、`reboot`、
  `tskill`、`chkdsk`、`cleanmgr` **不**标高危；现已补上。
- **不再被日常命令的"高危"标识淹**：`rm file.txt`、`mv a b`、`kill 1234`、
  `npm run format`（原先居然判高危）、`Stop-Process` 等不再标高危。
- **内核会更常向你请求审批**（+18 条，124 条语料口径）：`git push -f`、`git clean -xdf`、
  `git checkout -- .`、`git restore .`、`git stash drop`、`git branch -D`、`takeown /f`、
  `reg delete`、`drop schema`、`DELETE FROM`、`kubectl delete`、`terraform destroy` 等。
  这些均为不可逆或系统级操作；若某条你觉得问得太频繁，**改一处即可**：
  在 `shared/high-risk.mjs` 里把该条的 `tags` 由 `['approval','sign']` 改为 `['sign']`
  （降为 T2"标而不问"），并在 `KNOWN_DIVERGENCE.signOnlyRules` 登记 —— 测试会立刻校验一致性。

分叉率从 52.7% 降到 4.8%，且**漏标为 0**（剩余分叉全是单向 T2）。

## 4. 已知取舍（勿误当缺陷）

1. **读侧默认放行**：`YFW_FS_GUARD` 读侧默认 `warn`，即"允许根之外也能读"。
   原因：合法用途就是"用户打开的任意文件"（目录选择器起手目录是用户主目录、
   知识库读取需访问数据根）。凭据文件（`settings.json`/`auth.json`）**例外，读也拒**。
2. **写侧默认只做 deny 过滤**：未设 `YFW_FS_WRITE_ROOTS` 时，允许根之外的普通路径**仍可写**。
   要完全收紧就显式配置 `YFW_FS_WRITE_ROOTS`。该残留已被测试显式钉住
   （`server/bridge-fs-guard.test.mjs` 的"默认级别的已知残留"用例），不会被误当已修复。
3. **`/install-skill` 不加写拒绝**：它按设计要写数据根 `skills/`，加拒绝会破坏功能；
   只对它加了读侧闸门。
4. **PDF 预览 iframe 无 sandbox**：内容是 `application/pdf`（Chrome 插件渲染，不进入嵌入方 DOM），
   加 sandbox 有打断查看器的风险，收益低，故不加。

## 5. 应急回滚

| 症状 | 处置 |
|---|---|
| 文件读写被误拦 | `YFW_FS_GUARD=off`（立即回到加固前行为） |
| 预览打不开 / 界面异常 | `YFW_CSP_MODE=off` |
| 大文件预览 413 | 调高 `YFW_RAW_FILE_MAX_BYTES`（如 `134217728`） |
| 令牌 401（打包版） | 检查 `electron/main.cjs` 的 `TRUSTED_FRAME_ORIGINS` 是否含 `file://` 与 dev 源；帧信任判定见 `electron/bridge-frame-trust.test.mjs` |
