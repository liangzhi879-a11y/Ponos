## 〇、一页速览

**要做什么**：在左侧功能标签栏新增 `apps`（「应用智控」，与会话/任务/智能体/技能/工作流平级）。
用户输入**网站网址**或**应用程序路径**，由 **LLM 生成该目标的 CLI（App Spec）**，
套成**自动化智能控制台**，并可被应用配置的 LLM + 内核驱动执行。

**两条不可动摇的设计红线**：

> **红线一：工具默认不进入公共注册表。**
> 应用能力**仅在用户进入「应用智控」并打开某个具体应用卡片时**，才按需绑定给 agent；
> 离开即解绑。绝不全局暴露——避免几十个应用的命令把工具池撑爆、干扰模型选择。

> **红线二：不为每个目标生成"独立 CLI 程序"，而是生成声明式 `App Spec`（命令表）+ 通用运行器解释执行。**

**这不是新造架构**，而是复用项目**已有的四套成熟机制**：

| 复用对象 | 位置 | 复用方式 |
|---|---|---|
| **「工作流即工具」+ 可见性三态** | `kernel/dyntools.mjs` | ★ 直接对应"绑定才可见"；`app-tools.mjs` 与之**完全同构** |
| **四档审批 + 权限规则** | `kernel/approval-mode.mjs`、`kernel/permissions.mjs` | write 命令走既有审批 |
| **浏览器自动化** | `electron/browser-executor.cjs`（15 动作） | web 类目标的执行引擎 |
| **卡片 + 管理 UI** | `src/components/skills/SkillsPanel.tsx` | 卡片/菜单/删除直接照抄 |

### App Spec v1.1

```json
{
  "specVersion": 1,
  "appId": "app-7f3a2c",
  "name": "某某业务系统",
  "logo": "logo.png",
  "desc": "订单查询与库存核对",
  "target": { "type": "web", "url": "https://example.com" },
  "driver": "browser",
  "expose": { "mode": "console" },
  "auth": { "mode": "session", "loginUrl": "/login", "readySelector": "#main", "needsHuman": true },
  "commands": [
    {
      "action": "queryOrder", "title": "查询订单", "kind": "read",
      "params": [
        { "name": "orderId", "type": "string", "required": true, "description": "订单号" }
      ],
      "steps": [
        { "act": "goto", "url": "/orders" },
        { "act": "type", "selector": "#orderNo", "value": "${orderId}" },
        { "act": "click", "selector": "#search" },
        { "act": "wait", "ms": 1200 },
        { "act": "snapshot", "save": "result" }
      ],
      "returns": { "type": "table", "from": "result" }
    }
  ],
  "health": { "lastCheck": "...", "status": "healthy", "failures": 0 }
}
```

### ★ `expose.mode` 三态（红线一的落地）

| mode | 语义 | 工具可见性 |
|---|---|---|
| `private` | 只允许在控制台**手工执行**，永不接给 agent | ❌ 始终不可见 |
| **`console`** | **默认**。仅当用户**进入该应用控制台**时绑定给当前会话的 agent | ✅ 进入即可见 / 离开即消失 |
| `public` | 全局工具池（需用户**显式**开启，谨慎） | ✅ 全局可见（受 `LIMIT_DEFAULT` 截断） |

### 4.1 ★ `params` 采用数组（与工作流 `inputs` 同构）

**为复用 `deriveInputSchema(inputs)` 而刻意对齐**——该函数接收的是**数组**（`input_schema: { type, properties, required }`），
故 Spec 的 `params` 直接采用同构的数组形式，**零适配**即可派生 LLM 工具 Schema：

```json
"params": [
  { "name": "orderId", "type": "string", "required": true, "description": "订单号" }
]
```
> 与既有 `kernel/dyntools.mjs` 的 `wf.inputs` **完全同格式**。
> 若这里用对象 map，就必须额外写一个转换适配层——违背 DRY，故不用。

### `target.type` → `driver` 自动选择（按决策：都支持，首期即含桌面、且一步到位）

| target.type | driver 优先序 | 说明 |
|---|---|---|
| `web` | `browser` | 复用 browser-executor 15 动作 |
| `desktop` | ① `process`（自带 CLI）→ ② `script`（脚本接口，如 ase-cli 的 Lua）→ ③ `uia`（UI 自动化兜底） | **优先稳定接口**；探测到哪层用哪层 |

> **按决策：三级探测第 1 期即完整实现**（含 `script` 脚本接口注入），不做分期降级。
> 探测顺序是**降级链**：`process` 可用则不探 `script`，`script` 可用则不探 `uia`——
> 因为越往后越脆弱；`uia` 仅作最终兜底。

## 五、四大机制

### 5.1 识别与生成（按决策：**只做 LLM 生成**）

```
用户输入 URL / 路径
   ↓
① 机械探测（不调 LLM，纯采集）
   web     : 打开页面 → snapshot（DOM 结构 / 表单 / 表格 / 导航）
   desktop : 探测可执行文件特征、`--help`、脚本接口、安装目录结构
   ↓
② LLM 生成 Spec（用应用配置的 provider）
   输入 = 探测素材 + Spec JSON Schema ；输出 = 完整 spec.json
   ↓
③ Schema 校验（结构合法性，纯机械）
   ↓
④ ★ 实跑验证（不可省）
   挑 1-2 条 read 命令真实试跑
   ├─ 成功 → 采纳
   └─ 失败 → 把"真实报错 + 实际 DOM/输出"回喂 LLM → 修正 → 重试（≤3 轮）
   ↓
⑤ 人工确认（展示 Spec 摘要 + 试跑结果，用户确认才落盘）
   ↓
⑥ 落盘 registry + spec.json，抓 logo
```

> **如实提示**：LLM 生成的选择器**必然有幻觉**，一次成功率不高。
> 故 **④ 实跑验证 + ⑤ 人工确认** 是**强制环节**，构成"生成→验证→修正"闭环；
> 缺这两步，纯生成产出不可用。
>
> **澄清**："只做 LLM 生成"指**生成时机**，不等于每次进入都重新生成——
> Spec 生成后**持久化复用**（否则每次进控制台都重跑 LLM：慢、贵、不稳定）。

### 5.2 样式套版

| 维度 | 规则 |
|---|---|
| **版式选择** | 有 `returns.type=table` → 仪表盘版；全 `write` → 表单版；其余 → 终端版 |
| **表单自动生成** | `params` → 控件（`required` 标必填、`desc` 作提示），复用 `deriveInputSchema` 派生逻辑 |
| **结果渲染** | 按 `returns.type`：`table`→表格；`text`→富文本；`json`→树；`file`→下载项 |
| **品牌** | logo（自动抓 favicon / 提取 exe 图标）+ 主题色 |
| **安全标识** | read 标"只读"，write 标"需确认"（颜色区分） |

### 5.3 校验与更新（每次进入都校验）

```
进入控制台
  ↓ ① 完整性：spec.json schema 合法？依赖文件在？
  ↓ ② 可达性：URL 可访问 / 程序路径存在？
  ↓ ③ 保真性：抽样跑 1 条 read 命令，比对预期
  ↓ ④ 漂移检测：选择器/接口是否失效
  ↓
三态处置：
  健康    → 直接进入
  轻微漂移 → 自动修复（局部重新生成该命令）→ 备份旧版 → 提示用户
  严重失效 → 标「需重建」，但【不静默改】→ 交用户决定
```
> 原则：**可自动修复，但绝不静默改用户的东西**；每次自动修复前先 `spec.bak.<ts>.json`。

### 5.4 ★ Spec 编辑器（v1.1 新增，按"开放编辑"决策）

**形态**：**双视图**——
- **表单视图**（默认）：友好编辑 name/desc/commands/params，适合微调
- **JSON 视图**：直接改原文，适合高级修正

**能力**：
| 功能 | 说明 |
|---|---|
| 实时 Schema 校验 | 边编边校验，非法即标红 |
| 试跑按钮 | 单条命令就地试跑（**read 直接跑；write 走审批**） |
| 版本备份 | 保存前自动 `spec.bak.<ts>.json` |
| 一键回滚 | 从备份列表恢复 |
| 差异对比 | 与上一版 diff（LLM 自动修复后尤其有用） |

> **为什么值得开放**：LLM 生成不满意时，**手工改一个选择器比重新生成快得多**；
> 且 Spec 是纯声明式 JSON，改动风险可控（+Schema 校验 + 备份双保险）。

## 六、★★ 控制台绑定机制（红线一：工具不进公共注册表）

> 本节是 v1.1 的**核心增补**，直接实现"**只有使用应用智控、选特定卡片进入时才给 agent 接**"。

### 6.1 设计

**运行时绑定表**（主进程持有，`app-bindings.cjs`）——**严格单开**：
```js
// ★ 严格单开：sessionKey → 单个 appId（不是 Set，物理上不可能多开）
const activeConsoleApp = new Map()
```

**生命周期事件**（IPC，`electron/preload.cjs` 暴露）：
```
app:console:enter  (appId) → 绑定：activeConsoleApp.set(sessionKey, appId)
                             若已有绑定 → 先解绑旧的，再绑新的（原子替换）
app:console:leave  (appId) → 解绑：仅当当前绑定 === appId 才清除
                             （防止"A 离开"误清掉后绑的"B"）
```
> **严格单开的价值**：不是靠"约定只绑一个"，而是**数据结构上就是单值**——
> 从根上排除多开可能，工具池规模天然可控（最多一个应用的命令）。
> 若将来要放开多开，只需把单值改回 `Set`，改动面极小（`app-bindings.cjs` 一个文件）。

**内核侧只捞"当前绑定的应用"**：
```js
// kernel/cli.mjs 挂载（照既有写法扩展）
engine.tools.setDynamicTools(() => ({
  ...buildWorkflowTools({ roots: workflowRoots, engine: wfEngine, agentId: args.agent || null, publicLimit }),
  ...buildAppTools({ roots: appRoots, agentId: args.agent || null, activeApp: getActiveConsoleApp(sessionKey) }),
}))
```

**为什么"零重启就生效"**：`setDynamicTools` 接收的是**视图函数**（§1.2 证据：每次求值），
所以进入控制台后**下一个 turn** 就能看到新工具、离开后立刻消失——**无需重启内核、无需重建会话**。

### 6.2 可见性判定（与 `visibilityOf` 同构）

```
对每个应用 app：
  spec.expose.mode === 'private'  → 不可见（仅控制台手工执行）
  spec.expose.mode === 'console'  → 可见 ⟺ app.id === activeConsoleApp.get(sessionKey)   ← 默认
  spec.expose.mode === 'public'   → 可见（受 LIMIT_DEFAULT 截断）
```

### 6.3 三道防线叠加效果

| 防线 | 作用 |
|---|---|
| **① 默认 `console` 模式** | 不进公共注册表；不打开控制台就**根本不存在**这些工具 |
| **② 会话级绑定** | 绑定只对**当前会话**生效，不污染其他会话/其他 agent |
| **③ 严格单开（单值存储）** | 最多只有 1 个应用在线，工具数 ≤ 该应用命令数上限，**无膨胀可能** |

> 冗余价值：即便用户误把某应用设为 `public`，仍有 §7 的 `LIMIT_DEFAULT` 截断与 §八 的审批兜底。

## 七、与内核 + LLM 集成

```js
// kernel/app-tools.mjs（与 dyntools.mjs 同构）
export function buildAppTools({ roots = [], agentId = null, activeApp = null, publicLimit = LIMIT_DEFAULT } = {}) {
  const tools = {}
  const conflicts = []
  for (const app of listApps({ roots })) {              // 读 registry.json
    const spec = loadSpec(app.id)
    if (!isAppVisible(spec, { agentId, activeApp })) continue   // ★ §6.2 三态判定（严格单开）
    for (const cmd of spec.commands) {
      const preferred = `app_${slug(app.name)}_${cmd.action}`
      let name = preferred
      if (Object.hasOwn(tools, name)) {                 // 同 dyntools：不静默覆盖
        const alt = `${preferred}_${shortHash(app.id + cmd.action)}`
        name = alt
        for (let i = 2; Object.hasOwn(tools, name); i++) name = `${alt}${i}`
        conflicts.push({ app: app.id, preferred, resolved: name })
      }
      tools[name] = {
        description: `[${app.name}] ${cmd.title}${cmd.kind === 'write' ? '（写操作，需确认）' : ''}`,
        input_schema: deriveInputSchema(cmd.params),   // ★ 复用现有派生逻辑
        concurrencySafe: cmd.kind === 'read',
        run: async (args) => {
          const r = await invokeAppRunner(app.id, cmd.action, args)   // IPC → app-runner
          return { content: JSON.stringify(r), isError: !r.ok }
        },
      }
    }
  }
  Object.defineProperty(tools, 'nameConflicts', { enumerable: false, value: conflicts })
  return tools
}
```

**LLM 侧收益**：应用能力对模型表现为**普通工具**，无需改任何 agent 循环——
"由应用配置的 LLM + 内核驱动使用自动化能力"**自然成立**。

## 八、安全设计

### 8.1 必须修的缺口

动态工具 → `classifyTool` → `unknown` → 允许档位 `loose` → **默认放行**。
不处理则 write 命令**静默执行**，违背「write 需人工确认」。

### 8.2 双保险

**主机制 — 复用既有"显式规则优先"**（`decideToolPermission()` 已是 `deny > ask > allow` 且命中即定）
```js
// 应用绑定时注入规则
rules.allow.push(...spec.commands.filter(c => c.kind === 'read').map(c => toolName(app, c)))
rules.ask.push(...spec.commands.filter(c => c.kind === 'write').map(c => toolName(app, c)))
```

**兜底 — `classifyTool` 前缀规则（fail-safe）**
```js
// kernel/approval-mode.mjs，在返回 'unknown' 之前
if (/^app_/.test(name)) return 'appTool'  // 自有保守类，允许档 bypass
                                          // ⚠ 不能用 'write'：其允许档是 loose = 默认档 → 会被直接放行
```
> 效果：规则正常注入 → read 放行 / write 询问；
> 规则**未注入或失败** → 一律 `ask`，**宁可多问，绝不静默放行**。

### 8.3 其他约束

| 项 | 设计 |
|---|---|
| 绑定粒度 | 会话级（§6），不污染其他会话/agent |
| 工具池保护 | 沿用 `LIMIT_DEFAULT` 截断 |
| 执行留痕 | 所有调用（**含被拒绝**）写 `history/*.jsonl`，提供"我发过什么"查询 |
| 凭据存储 | 登录态加密存 `session.json`；**Spec 内禁止明文密钥**，密钥走环境变量 |
| 危险动作 | 删除/下发类标 `dangerous: true` → **强制 ask**（即便档位 bypass 也问） |
| 域名白名单 | 复用 `.yfworking/browser-whitelist.json` |
| **不做的事** | 不逆向协议、不注入未授权进程、不采集客户个人信息 |

## 十、实施计划（分 4 期；**desktop 进第 1 期**）

| 期 | 内容 | 验收标准 |
|---|---|---|
| **1** | 标签栏 + 注册表 + 卡片列表 + 新增对话框（手工填 Spec）+ **web 与 desktop 双驱动**（desktop 含 `process→script→uia` **三级完整探测**） | 能新增网站/桌面应用；卡片可见；能进控制台 |
| **2** | `app-runner` + Spec 执行 + 控制台渲染 + **控制台绑定机制（§六）** + 安全双保险 | 手写 Spec 能真跑通；进入才绑定、离开即解绑；write 必被询问 |
| **3** | `app-profiler` LLM 生成 + 实跑验证闭环 + `app-validator` 校验更新 | 给 URL/路径能自动产出可跑的 Spec |
| **4** | 套版三种版式 + `SpecEditor` + 接 `buildAppTools` 全量 | LLM 能调用应用能力；Spec 可编辑可回滚 |

**每期都做**：回归测试 + 审计留痕 + 文档更新。

> 说明：desktop **一步到位**（按决策）意味着第 1 期就要实现三级驱动探测
> （`process` → `script` → `uia`，含脚本接口注入），**工期与复杂度显著上升**——
> 这是本方案最大的工期风险，已在 §十一 标注。建议第 1 期内部仍按三级**逐个落地**：
> 先 `process` 跑通、再 `script`、最后 `uia`，每级都能独立验收，避免一次性验收失败。

## 十一、风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| LLM 生成 Spec 不可用（幻觉） | **高** | §5.1 实跑验证 + ≤3 轮修正 + 人工确认（强制闭环） |
| **动态工具默认放行（安全缺口）** | **高** | §8.2 双保险；**第 2 期前必须落地** |
| desktop 驱动探测复杂度（进第 1 期后） | **高** | 第 1 期先做 `--help` 级最小支持；三级探测逐期细化 |
| 工具池膨胀 | 中 | §6.3 `console` 默认 + 会话绑定 + `LIMIT_DEFAULT` 三道防线 |
| 用户误设 `public` 导致工具泛滥 | 中 | 需显式开启 + 二次确认 + 数量上限提示 |
| 网站改版致 Spec 失效 | 中 | §5.3 校验 + 自动修复 + 版本备份 |
| 登录态失效 | 中 | `auth.needsHuman` + 现成 `pause_for_human` |
| UI 自动化脆弱（桌面第三顺位） | 中 | 仅兜底；优先 CLI/脚本接口 |
| 敏感数据泄漏 | 中 | Spec 禁明文密钥；探测素材脱敏后再交 LLM；域名白名单 |

## 十二、决策点（v1.2 全部锁定）

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 工具是否进公共注册表 | ✅ **不进**，`console` 绑定模式（默认）；进入卡片才绑定 |
