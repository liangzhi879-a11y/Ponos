## 0. 环境准备

调试版目录：`release/YFWorking`；GUI 走静态 `dist/`，内核按会话 spawn。

| 目的 | 做法 |
|---|---|
| 让界面显示新版本 | 重启应用（桥与 GUI 启动时加载）；**内核新建会话即生效**，无需重启 |
| 清掉旧的健康快照（避免旧红档复活干扰判断） | DevTools 执行 `localStorage.removeItem('yfworking-health')` 后刷新；或换一个新会话 |
| 触发一次压缩（验「记忆失真」轴） | 二选一：**(a) 最省事**——往对话里粘贴大段文本（长文件/长日志）把上下文顶到压缩阈值，压缩会自动发生并跑保真审计；**(b) 要快速复现**——在设置里把 provider 的 `contextWindow` 配成小值（如 8000）并**使用不在内核模型表里的模型**。⚠️ 内核模型表（`deepseek-v4-flash`、`deepseek-v4-pro`、`MiniMax-M3`）**优先于**该配置；且桥会把 provider 的窗口值注入 `CLAUDE_CODE_AUTO_COMPACT_WINDOW`，**覆盖**你在系统里设的同名变量——所以直接设系统环境变量无效。注：`/compact` 只在 UI 命令列表里，内核不处理该斜杠命令 |
| 让失真更容易亮（省时间） | 启动前设 `PONOS_FIDELITY_AMBER=20`、`PONOS_FIDELITY_RED=50`（这两个不被桥覆盖，系统级设置有效） |
| 临时关掉失真判定（对照用） | 启动前设 `PONOS_FIDELITY=0` → 应完全不出现角标/卡片/泛光 |
| 关掉 LLM 保真审计（只看确定性审计） | 启动前设 `PONOS_FIDELITY_LLM_AUDIT=0` |

`PONOS_FIDELITY_*` 系列经 `buildChildEnv()` 的 `...process.env` 透传到内核且桥不做覆盖，故系统级设置即可生效。

## 1. 两个被测量互不干扰（核心主张）

| # | 操作 | 期望 |
|---|---|---|
| 1.1 | 开新会话，正常对话几轮 | 血条随上下文消耗变短/变色（**压力**）；**无**失真角标、**无**卡片、**无**泛光 |
| 1.2 | 继续对话直到血条进入红色档（粘大段文本可加速逼近） | 血条变红，但**依然没有**失真角标/卡片/泛光（压力红≠失真红） |
| 1.3 | 记下 1.2 状态下血条填充色 | 后续任何"失真红"都不应改变该颜色（颜色只跟压力走） |

## 2. 失真：不打扰 → 打扰

| # | 操作 | 期望 |
|---|---|---|
| 2.1 | 让助手读一个**不存在**的文件并让它引用该路径（如「请读取 `src/__nope__.ts` 并说明里面的配置」） | 该轮结束后至多出现 **amber 角标**（带条数），**不弹卡** |
| 2.2 | 下一轮继续引用同一路径 | 证据跨轮升级 → **红色角标 + 弹出证据卡**；卡片逐条列出：第几轮 · 轴（记忆失真/自相矛盾/目标漂移）· 具体证据 |
| 2.3 | 观察血条与泛光 | 泛光出现（已换轴到失真）；血条颜色**不变**（仍按压力） |
| 2.4 | 卡片上查看按钮 | 应有「重新锚定」（主）、「新建会话（锚点+摘要）」、「关闭」、最小化 |
| 2.5 | 点最小化 | 折叠为右下角小胶囊；**不带冷却**，点一下可恢复展开 |

## 3. 轻动作：重新锚定

| # | 操作 | 期望 |
|---|---|---|
| 3.1 | 点「重新锚定」 | 出现**可编辑**的锚点预览（原始任务 + 会话记忆 + 硬约束，≤4KB） |
| 3.2 | 点「发送锚定」 | 锚点作为**一条可见 user 消息**自动发出（不是只填进输入框） |
| 3.3 | 发送后 | 角标在数秒内**回绿**；卡片消失；观察期内（默认 3 轮）同一证据不再弹 |
| 3.4 | 回绿后读 `bridge` 日志或 DevTools Network | 应有一次 `POST /session/anchor-applied`，返回 `{ok:true}` |
| 3.5 | 断网/桥未起时点发送锚定 | 本地照常回绿（上报静默失败），不应报错或卡住 |

## 4. 复发（本轮新修）

| # | 操作 | 期望 |
|---|---|---|
| 4.1 | 完成 3.1–3.3 后，再次让助手引用同一个不存在的路径（两轮） | 卡片**重新弹出**，并显示「此前处理过的失真再次出现 —— 重新锚定未能根治」提示 |
| 4.2 | 观察按钮强调色 | 「新建会话（锚点+摘要）」成为主按钮（动作升级） |
| 4.3 | 不处理，继续对话 | 该复发态**不再反复弹卡**（只提醒一次，避免无限循环） |

## 5. 冷却语义（本轮新修）

| # | 操作 | 期望 |
|---|---|---|
| 5.1 | 点「重新锚定」处理掉一处失真，随后在 5 分钟内制造一处**不同**的失真（换一个不存在的路径） | **应立即弹卡**（新证据不被旧冷却闷住） |
| 5.2 | 改为点「关闭」，再制造新的失真 | 5 分钟内**不弹卡**（冷却只由显式关闭设置），但角标仍应点亮 |

## 6. 重动作：新建会话（锚点+摘要）

| # | 操作 | 期望 |
|---|---|---|
| 6.1 | 点「新建会话（锚点+摘要）」 | 源会话任务被停止；新会话创建；输入框预填**锚点在前、摘要随后**（**不自动发送**，由你确认） |
| 6.2 | 检查源会话 | 保持只读可回溯，内容未被清空 |
| 6.3 | 取消勾选「携带摘要」再点一次 | 预填内容只剩锚点 |

## 7. 向后兼容与持久化

| # | 操作 | 期望 |
|---|---|---|
| 7.1 | 打开一个**旧会话**（其快照无 `distortion` 字段） | 不显示角标/卡片/泛光（缺省即健康），血条照常工作 |
| 7.2 | 重启应用后打开有失真的会话 | 角标/卡片从持久化快照恢复；已展示过的证据不重复弹 |
| 7.3 | 升级前就存在的 `yfworking-health` v1 快照 | 能正常读取（migrate 补默认值），**不出现界面崩溃** |

## 8. 反例（不该发生）

- ❌ 压力档红档触发失真卡片（应按 1.2 只变血条颜色）
- ❌ 血条颜色跟着失真档变化（应只跟压力档）
- ❌ 同一证据反复弹卡
- ❌ 「重新锚定」点了没有反应（只填输入框未发送）或发送空锚点
- ❌ 无失真的长会话里莫名出现角标（误报）
- ❌ 失真判定报错导致对话中断（应静默降级，对话照常）

## 9. 发现问题时请附上

1. 复现步骤与期望/实际
2. 会话的 `ponos_health` 事件（DevTools 里过滤 `distortion`）
3. 若是误报：那段对话里"上下文到底有没有真失真"（这决定是阈值问题还是判定逻辑问题）
