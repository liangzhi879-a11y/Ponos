# 应用智控 · 使用说明

> **速览**：给一个网址或桌面程序，应用智控让模型把它写成一组可执行的「命令」，让 AI 在你允许的范围内替你操作它。默认只有**打开这个应用卡片**的会话里 AI 才能用这些命令，离开即收回；写操作一定先弹确认。生成结果**不会自动落盘**，必须你看过预览、点「确认并保存」才算数。

## 1. 这是什么

你提供一个「网址」或桌面程序的「可执行文件路径」，应用智控据此让模型写出一套目标的**命令表**（App Spec），再把它接成 AI 可调用的能力。AI 能不能操作、能操作到什么程度，由你设置的范围决定。

## 2. 新增一个应用

1. 点左侧功能栏**第六个标签「应用智控」**。
2. 点「**新增应用**」（列表里的虚线卡位，或右上角按钮）。
3. 填：
   - **应用 ID**（只能字母 / 数字 / 短横线 / 下划线）
   - **名称**、**描述**
   - **目标类型**：`网站` → 填**网址**；`桌面应用` → 填**可执行文件路径**
4. 点「**生成命令**」。
5. 看**预览**（命令清单 + 试跑结论）。不满意可点「**重新生成**」，或点「**手工编辑 JSON**」自己改。
6. 点「**确认并保存**」。

> 也可以先点「**探测**」：只做真实探测、不调模型，确认目标能被打开 / 识别。生成前请先把 ID、名称、目标填好。

## 3. 点「生成命令」之后会发生什么

1. **真实探测**。网站：真的打开页面、抓一份快照；桌面：依次尝试 CLI 帮助、脚本接口、UI 自动化，**命中即停**。这一步不调模型，只是采集。
2. **模型写命令**。把探测素材交给模型，让它输出完整的命令表；输出不合法 / 结构不对就**回喂修正，最多 3 轮**。
3. **试跑验证**。只试跑**查询类（read）**命令，**最多 2 条**，且**跳过需要填参数的**；**写操作（write）绝不试跑**——避免在你不知情时改动真实数据。
4. **人工确认**。结果**不落盘**，必须你点「确认并保存」。

**进度怎么看**：界面显示的是**真实进度**——当前阶段、已接收字符数、已耗时、模型输出的实时内容。**没有百分比进度条**，因为百分比无法真实计算，所以不编。失败时显示模型的**原始报错**；超时 / 中断也会**保留已经收到的半截内容**供你排查。

## 4. 试跑没通过怎么办

保存按钮会被**禁用**（试跑没通过不让存）。两个选择：

- 点「**重新生成**」再试一次；
- 点「**手工编辑 JSON**」，自己把不对的地方改掉。

## 5. AI 什么时候才能操作它

默认是「**仅本控制台会话**」：**只有当你进入这个应用卡片时**，AI 才拿到这些命令工具；**离开卡片就断开**。这是刻意设计——不把一个应用的能力变成所有会话都能用的全局工具。

在「编辑 Spec → AI 可见范围」里可切换三种：

| 范围 | 含义 | 风险 / 适用场景 |
|---|---|---|
| **仅本控制台会话**（默认） | 进入卡片才对当前会话可见，离开即失效 | 风险最低，日常首选 |
| **全局可用** | 所有会话都能用，不必进入卡片 | 命令会**常驻工具池**，任何对话里的 AI 都可能调用它（写操作仍会弹确认）。适合你确实希望「随时随地可调用」的常用应用 |
| **仅手工执行** | AI **永远**拿不到，只能你在控制台点按钮跑 | 最安全。适合敏感 / 危险应用，或只想人工操作 |

> 「全局可用」需你**显式选择**：默认校验会拒绝 `public`，只有你在 Spec 编辑器里主动选了「全局可用」并保存，才会放行（界面上会有一段红字提醒其影响范围）。选它意味着**所有会话**（包括你没进这个卡片时）的 AI 都能调用这些命令。

> 实现层面已验证：进入卡片会绑定，内核随即产出带 `app_` 前缀的工具，离开即消失（文件级端到端测试覆盖）。但「真实机器 + 真实模型」下**由 AI 实际发起的调用**尚未端到端验收，若发现异常请反馈。

## 6. 为什么写操作会弹确认

写操作会**改动真实系统**（提交表单、改数据、下发 / 删除），所以固定走「**询问**」：无论审批档位多松，AI 调用写命令前都先问你。查询类（read）在进入卡片后可直接执行。

## 7. 桌面应用：三级驱动与降级时机

桌面目标按「稳定优先」的顺序依次尝试，**命中即停**：

**进程探测（CLI）→ 脚本接口 → UI 自动化**

前一级不可用才降级到下一级；越往后越脆弱，UI 自动化只是最后的兜底。

「UI 自动化」这一级的后端**当前未接入**（需要原生依赖）。探测不到时会明确报「**未接入**」，**不会假装成功**——假装成功会让命令静默空转，比直接报错更危险。

## 8. Spec 存在哪、怎么手改、怎么回滚

- 路径：`~/.yfworking/apps/<appId>/spec.json`（本机通常在 `C:\Users\<你>\.yfworking\apps\...`）。
- 在卡片里点「**编辑 Spec**」，可**表单 / JSON 双视图**编辑；**保存前会校验，不合法就不保存**。
- 「**历史版本**」里可回滚；**回滚本身也会先备份当前版本**，所以随时能再切回来。

## 9. 校验三态

进入卡片时会做一次自检，结果三种：

| 状态 | 含义 | 处置 |
|---|---|---|
| `healthy` | 正常 | 直接可用 |
| `drifted` | 有漂移信号（目标可达，但接口 / 选择器可能已失效） | 可点「尝试修复」 |
| `broken` | 目标本身不可用（URL 非法 / exe 不存在等） | **不自动修复**，要先修目标本身 |

## 10. 「尝试修复」

它只修「**最近一次执行失败**」的命令（依据执行历史），其余命令原样不动。写盘前**自动备份**，改完对**整份 Spec 再校验一次**，不合法就**整体放弃**（宁可不修，不可改坏）。改了什么会**列出来给你看**，不会静默改。

> 补充：一次最多处理若干条失败命令，当前实现上限 5 条。

## 11. 已知限制（如实说）

- 模型生成**必然会出错**，所以有「试跑 + 人工确认」两道关。
- 试跑**跳过了需要参数的查询命令**，所以「试跑通过」**不等于**「所有命令都验证过」。
- 同一毫秒内**快速连续保存**，可能覆盖同一份备份。
- **完整真机链路（真实页面 + 真实模型）尚未端到端验收过**。

## 12. 常见问题

- **点了没反应？** 先确认应用**已重启、加载了新版本**。
- **生成失败，提示鉴权 / 模型名？** 去**应用设置检查模型配置**（provider / API Key / 模型名）。
- **页面改版后命令失效？** 用「**尝试修复**」，或「**编辑 Spec**」手工改相应的选择器 / 接口。
