# 修复：Electron 打包版渲染层请求被桥 401（Unauthorized）

- **日期**：2026-09-17
- **症状**：打包版（`release/YFWorking`）里，工作流面板 / 知识库面板显示 `Unauthorized`，知识库读不出内容。
- **定位**：桥侧 `server/bridge.mjs` 的 S2-D2 令牌闸（`server/bridge-token.cjs:authorizeBridgeRequest`）
  把打包版渲染层的 HTTP 请求整体判为"无 Origin 且无令牌" → 401。

## 1. 根因（实测，不是推断）

`authorizeBridgeRequest` 的判据是"**有 Origin 就走来源白名单，无 Origin 必须持令牌**"。
S2-D2 落地时（2026-09-16）的依据是：浏览器 `file://` 页面发起的跨源 fetch 会带 `Origin: null`。
该依据在**旧内核**成立，在打包版所用的 **Electron 43.2.0 / Chromium 150** 上不成立。

同一 URL、同一桥、同一时刻的对照实验：

| 运行环境 | `fetch('http://127.0.0.1:51517/list-dir?...')`（file:// 页面） |
|---|---|
| 系统 Chrome（headless，较新） | `FETCH_STATUS=200`（请求带 `Origin: null`） |
| `electron.exe` 43.2.0 / Chromium 150 | `FETCH_STATUS=401` + body `{"error":"Unauthorized"}`（请求**无 Origin**） |

复现方法（一次性诊断脚本已按用户要求清理，要点在此留存）：

1. 闸门侧：起一个本机 HTTP 服务，**记录收到的 `origin` 与 `x-yfw-bridge-token` 两个头**，
   按令牌是否正确回 200/401（与 `authorizeBridgeRequest` 同判据）。
2. 客户端侧：`BrowserWindow.loadURL('file:///…/probe.html')`，页面里 `fetch('http://127.0.0.1:<port>/…')`，
   用 `webContents.executeJavaScript` 读回页面内的状态文本。
3. 对照两次加载：一次未装注入器、一次先 `installBridgeTokenHeaderInjector(session.defaultSession, …)`。
   ⚠️ 两次必须用**不同 query**（仅改 hash 不会重新加载，页面不会重新发 fetch，会读到上一次结果）。
4. 装注入器前的真机结果 —— 服务端实收 `{origin: null, token: null}` → 页面 `401 {"error":"Unauthorized"}`；
   装了之后 —— `{origin: null, token: <注入值>}` → 页面 `200`。

线上日志实证（`~/.yfw/logs/renderer-console.log`）：

```
[render:console] [FileBrowser] error: Unauthorized (.../dist/assets/index-D3v6KZSR.js:53)
```

对应 `src/components/files/FileBrowser.tsx:46`（把后端 `{error}` 原样回显）；知识库面板空态
内嵌了同一组件（`KnowledgeEmpty.tsx` / `KnowledgeTree.tsx`），故两处症状同源。

## 2. 修复（main 侧统一注入令牌，渲染层零改动）

渲染层有 58 处 fetch 散在 27 个文件，逐处改不现实 ⇒ 在唯一入口处注入：

- **新增** `electron/bridge-header-inject.cjs`：零 electron 依赖的注入器
  - `createBridgeHeaderInjector({port, token, headerName})` 纯函数（按 host 精确匹配 `127.0.0.1:<port>`，
    协议限 http/https/ws/wss，已有同名头不覆盖，非桥请求绝不注入 → 令牌不外泄）；
  - `installBridgeTokenHeaderInjector(session, opts, seen)` 装到 session 的 `onBeforeSendHeaders`，
    同一 session 重复装会被拒（后注册会覆盖先注册的处理器）。
- **改造** `electron/main.cjs`：`app.on('session-created')` 覆盖后续 partition，
  `app.whenReady()` 内对 `session.defaultSession` 显式安装（defaultSession 早于监听建立，
  且必须早于任何窗口创建）。令牌与 `/boot-status`、WS、诊断、桌宠**同一枚**。
- **补预检声明** `server/bridge.mjs`：`Access-Control-Allow-Headers` 增加 `x-yfw-bridge-token`
  （自定义头一旦触发预检而未被声明，真实请求根本不发，表现为 `Failed to fetch` 而非 401）。

安全边界未削弱：无 Origin 又无令牌的请求（`<img>`/`<script>`/表单型 CSRF 面、本机其它进程）**仍然 401**，
D2 的收益不变；令牌只注入本桥 host。
