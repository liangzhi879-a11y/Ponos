- 文档原文：**主循环与 lane 各有一份守卫实现**，同一逻辑两处维护，是 v2 核查中最实在的技术债。

## 1. 核查结论（代码级，非采信文档）

`kernel/engine.mjs`（本轮 2,966 行）确认存在**四组**两侧重复，且内注释逐条自认：

| 组 | 主循环（`runTurnInternal`@914） | 子 lane（`runSubAgentLoop`@2106） | lane 侧自认注释 |
|---|---|---|---|
| R3-2 失败自愈标记 | `hadToolError` 三态 | 同，**文本逐字相同** | 「子 lane 镜像」 |
| 守卫⑥ 进展刷新 | `madeProgress` 口径 | 同，**逐字相同** | 「镜像主循环」 |
| 守卫⑤ 同工具提醒 | 阈值命中 + 注入文案 | 同，**文案逐字相同** | 「审计 #10」 |
| 守卫④ 错误熔断 | `allFailed` + 预算 + 文案 | 同判据，**文案不同** | 「审计 #4」 |

**为什么这是真债**：审计 #4 记录了实际后果——子 lane 曾**没有**错误熔断，连续全败会一路空转到迭代上限（护栏只做了一半）。根因就是"两处维护、改一处忘另一处"。

## 2. 本轮范围：只消除重复，不做整文件拆分（附理由）

文档字面含两件事：① 拆 `engine.mjs`；② 消除双份守卫。

**本轮只做 ②，理由**：
1. **收益/风险比**：① 是纯搬移（不改行为但改动面覆盖整个 2966 行、涉及闭包捕获的大量可变状态），在**无独立提交**的工作区里（当前 167+ 项未提交改动）做整文件搬迁，一旦出问题极难二分定位；② 是**行为收敛**，直接消灭"两处维护"这一债务本体，且可被测试完整覆盖。
2. **① 依赖 ②**：若先拆文件，两份守卫会被搬到两个模块，重复仍在、反而更难收敛。
3. 文档把"双份守卫"点名为「**最实在**的技术债」——先消灭最实在的。

⇒ spec 记录：**P1-6 拆分子项 ① 未做**（诚实标注，见清单）。

## 3. 提取边界（关键设计决策）

**收敛**（两侧必须一致）：
- 判据：进展口径、全失败判定、三态错误标记、阈值命中、预算是否还有
- 文案：同工具提醒（两侧逐字相同）、熔断引导（同源、按 variant 分化）

**刻意保留在 engine.mjs**：
- **状态推进**（`streak++` / `= new Set()`）：一行直白赋值，抽函数只增间接层，还要把可变状态在两侧传来传去
- **副作用**（`pushMemory` / `session.appendUser` / `store.appendUser` / `wire.system` 事件）：两侧**故意不同**——主循环面向交互用户（发 `guard_heal` 事件、可继续交互），子 lane 面向后台任务（`guardStop` 收尾）。强行统一＝改变既有行为
- **阈值常量**（`MAX_ERROR_ITERATIONS` / `REPEAT_REMIND_AT` / `MELTDOWN_HEAL_MAX`）：仍以 engine.mjs 为单一真相源（受 `LOOP_GUARD_OFF` 与 env 控制），**由调用方传入**，`guards.mjs` 不复制常量值

**熔断文案为何不统一**：主循环面向交互用户，文案含明确排查手段（Read 文件/日志、看上一轮 `tool_result` 的 stderr）；子 lane 无交互对象，文案更简、要求"输出阻塞说明"。⇒ 收敛为**同一函数 + variant**（`'main'` / `'lane'`），既消除重复又保留差异且差异可见。

## 4. 约束

- `guards.mjs` **纯函数**：无 IO、无状态、**不导入 engine.mjs**（避免循环依赖）
- 导出 7 个：`isRealProgress` / `allToolResultsFailed` / `nextHadToolError` / `shouldRemindRepeat` / `repeatRemindText` / `errorMeltdownText` / `hasMeltdownBudget`
