# S4 · 文件协同（模态分层 / 版本链 / 软占用与检出检入 / 冲突处置）

> 上游总设计：`2026-09-14-team-collaboration-design.md`（下称"总设计"）。总设计 §0 规定"S3–S5 的详细设计各自另开 spec"，本文即 S4 的详细设计。
> 依赖：**S1 已完成**（三路合并原语 `shared/office-merge.mjs`、ops 契约、`baseVersion`）、**S3 已完成**（`shared/team-source.mjs` 的 CAS 路径 / 校验写 / 占位符检测 / 副本吸收，`kernel/team-store.mjs`、`kernel/team-sync.mjs`）。

## 0. 前置闸门（已由用户裁定）

| 批注 | 问题 | **裁定** | 落地含义 |
|---|---|---|---|
| **#3** 软占用默认 | 谁在编辑某文件的提示/占位，默认是否开启 | **全局默认关闭 + 按目录开启** | 占用是**按目录 opt-in** 的能力：`team.json`（或目录策略文件）里显式开启才生效；默认下不产生任何占用文件、不打断任何编辑。 |
| **#9** L-D 检出/检入 UX | 如何提示"某人正在编辑，你目前只读"、如何引导"检入" | **显式"检出/检入"按钮 + 顶栏状态条** | 只读态与占用态**在顶栏常驻可见**；检出/检入是**显式动作**，不做"打开即自动检出"。 |

**仍未确认的批注（按总设计纪律处理，不擅自定策）**：
- **#8 团队源体积上限**：L-D 类大文件是否进团队源、有无单文件上限 ⇒ 本轮**只度量 + 参数化**（沿用 S3 对 #6/#7/#10 的处置惯例：给公开默认值 + 可配参数，不阻断、不擅自裁剪）。

## 1. 范围

**做**（对应总设计 §5.1 / §5.3 / §5.4 / §5.7 / §5.8 / §10-10）：

1. **文件模态分层判定**：`L-A 可合并 / L-B 可提取 / L-C 可转换 / L-D 不可解析`，判据是"**是否存在稳定寻址单元且可回写**"，不是文件类型的函数（总设计 §5.1）。
2. **三层兜底的能力探测**：先转换（`doc_toolkit.py convert`）→ 再提取（既有知识导入）→ 最后降级（L-D 检出式）。**不重新实现转换器**（总设计明列）。
3. **文件版本链**：`fileId` 与路径解耦、`versionId` = 内容哈希、路径变更历史；**一律追加、永不原地改**；**临时/备份文件不用 `.bak` 命名**（总设计 §5.7 与定案 3 的补充）。
4. **L-B 语义**：只追加版本、**永不原地写**（这是 §10-10 的头号验收断言）。
5. **软占用**：`advisory claim + 租约 + 心跳 + 可接管`（总设计 §5.3），按 #3 裁定**默认关闭、按目录开启**。
6. **L-D 检出/检入**：同一时刻仅一人可检出、他人只读；租约超时后可接管；检入生成新版本（总设计 §5.1 L-D、§5.3）。
7. **冲突处置**：四选一（接受对方 / 保留我的 / 另存副本 / 进编辑器）的**决策层**，其中"另存副本"的结果**降级为草稿**（总设计 §5.4）。
8. **最小 UI 接线**：顶栏状态条（占用/只读/已检出）+ 检出、检入按钮 + 冲突处置对话框（承载 #9 的裁定）。

**不做**（明确边界，避免范围蔓延）：

- 不重新实现格式转换器（复用 `doc_toolkit.py convert`）。
- 不改 S1 的合并原语与 ops 契约；S4 只**调用**它们。
- 不把 docx 降维成 markdown 以求"可合并"（总设计 §12-7 明确不做）。
- 不新建同步机制（不引入 fs.watch / 共享数据库 / 锁文件做正确性依据）。总设计定案 8：**锁不得参与正确性**，正确性建立在内容哈希 + 乐观并发上。
- 不做全量 UI 重构：仅在既有编辑器外壳上**加**状态条与按钮。

## 2. 数据模型（全部 append-only，落 S3 已备好的路径）

| 对象 | 位置（S3 `TEAM_LAYOUT` 已提供） | 形态 |
|---|---|---|
| 版本链 | `versions/<fileId>.jsonl` | 逐行：`{type:'bind', fileId, logicalName}` / `{type:'path', path, at}` / `{type:'version', versionId, bytes, authorId, at, note, modal}` |
| 内容 | `cas/<hash>` | 内容寻址（文件名 = 内容哈希 ⇒ 同名必同内容，天然免疫网盘冲突副本） |
| 占用/检出 | `claims/<fileId>.jsonl` | 逐行：`{type:'claim', holder, deviceId, at, leaseMs, note}` / `{type:'release', holder, at}` / `{type:'heartbeat', holder, at}` / `{type:'takeover', from, to, at, reason}` |
| 策略 | 目录策略文件（按 #3：opt-in） | `{softClaim: false\|true, occupancy:'advisory'\|'exclusive', maxFileBytes?: number}` |

**为什么 fileId 不能由内容派生**（与 S1 的 `blockId` 相反）：`blockId` 标识"这一块内容"，内容变则 id 变是**特性**；`fileId` 标识"**这一个文件**"并要串起它的全部历史版本，内容一变就换 id 会让版本链断裂。故 `fileId` 在首次纳入团队源时**一次性分配**（随机 12 位 hex），此后由 `versions/<fileId>.jsonl` 的 `path` 行记录路径变更史。代价：需要一次"路径 → fileId"的解析（扫描 `versions/*.jsonl` 的 `path` 行，取最新绑定）。可逆性：高（派生规则可换，历史日志不用动）。

**versionId = 内容 sha256**：与 S1 的 `baseVersion` 同源，天然一致，无需转换。

## 4. 子步骤（每步一个可独立验收的产物）

| 步 | 内容 | 验证方式 |
|---|---|---|
| 1 | `shared/file-modal.mjs` + `shared/file-modal.test.mjs` | 单测：四层判定的代表格式与边界（含 `.doc/.xls` 归 L-C、`pptx/psd/zip` 归 L-D、`pdf/png` 归 L-B、`docx/xlsx/md` 归 L-A）；三层兜底决策表（转换可用→升层；不可用→提取；再不可用→降级 L-D）；**能力探测如实报告**（本机无 `win32com` ⇒ `.doc` 不可转换） |
| 2 | `kernel/file-collab.mjs` 版本链部分 + 测试 | 单测：纳管生成 `fileId` 且 `cas/<hash>` 落盘；**追加语义**（同内容重复纳管不产生重复版本；改内容产生新版本且旧版本可读）；`versionId` 与内容 sha256 一致；**路径变更写 `path` 行且历史可查**；**不产生 `.bak` 文件**（断言目录内无 `.bak`） |
| 3 | L-B 语义（只追加、永不原地写） | 单测（**§10-10 头号验收**）：对 L-B 文件执行"纳管/写"⇒ 目标文件**字节不变**（哈希对照），且用户**原始目录里不产生任何新文件**；尝试原地写 ⇒ 明确拒绝（错误码）而非静默 |
| 4 | 软占用（#3 默认关闭 + 按目录开启） | 单测：默认（未开启）⇒ **不写任何占用记录**、不报占用、不影响编辑；开启 ⇒ 占用可见、他人获得"他人正在编辑"提示；租约到期后可接管；显式释放；心跳续租 |
| 5 | L-D 检出/检入（#9 显式动作） | 单测：A 检出后 B 检出**被拒**（且告知持有者与剩余租约）；B 只读；A 检入 ⇒ 生成新版本且占用释放；租约超时 ⇒ 他人可接管（记录 `takeover`）；未检出者检入被拒 |
| 6 | 冲突处置决策 + 接线 | 单测：四选一各自的结果（接受对方=用 theirs、保留我的=用 mine、另存副本=**新草稿**且原文件不动、进编辑器=交给 S1 合并后落盘）；`我方无改动`/`对方无改动` 的退化情形；**副本降级为草稿**（不产生"同目录多份近似文件"） |
| 7 | bridge 路由 + 最小 UI + 门禁 | 真机测试：路由鉴权与状态码；`tsc`；全量门禁；UI 只加状态条/按钮/对话框 |

## 6. 已知限制与待验证（如实记账）

1. **旧格式升层无法在本机端到端验证**（实测）：`.doc→.docx` 依赖 `win32com`（本机**未安装**，且仓库内**没有任何真实 `.doc/.xls` 语料**，`xlwt` 亦缺失 ⇒ 也造不出 `.xls` 样本）。因此本 spec 的验证策略是：
   - **可验证**：能力探测（如实报"不可用"）、调用封装（参数拼装、错误传播、超时）、**失败后的降级路径**（这正是三层兜底的实际价值），以及"降级后不产生原地写"。
   - **待验证**（登记终验）：装有 Word/pywin32 的环境里 `.doc→.docx` 的实际转换成功路径；`.xls→.xlsx` 在提供真实样本后的实际转换。
   - 结论：**不把"未验证"写成"已验证"**；验收表里对该项标注为"受限"。
2. **软占用是 advisory（建议性）**：总设计定案 8 明确"锁不得参与正确性"。占用只影响 UX 提示与 L-D 的串行化，**不阻止**底层写入；正确性仍靠 `baseVersion`/内容哈希。
3. **#8 体积上限未定**：本轮只度量（报告单文件字节数并可作为参数传入），不阻断。
4. **L-B 的"提取物入知识空间"**：复用既有 OCR/导入链路，S4 不新建提取器，只记录"应提取"的意图与版本锚点（总设计 §5.1：引用锚定版本 id 而非路径）。

## 7. 可逆性

- 模块新增（不改既有语义），可整体停用：关闭目录策略即回到"无占用、无检出"的 S1/S3 行为。
- 版本链是**新增日志目录**，不影响既有文件读写路径；删除 `versions/`/`claims/` 不影响用户文件本身。
- 冲突处置只**产出决策**，落盘仍走 S1 的 ops 契约 ⇒ 回滚点清晰。
