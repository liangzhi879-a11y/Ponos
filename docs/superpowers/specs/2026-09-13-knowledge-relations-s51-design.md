# S5.1 增量设计：条目级图谱层级 + 引用接入（ref 类型）+ 伪链接修复

> 前序：`2026-09-13-knowledge-relations-design.md`（S5，已交付并合并 main `69e149e`）
> 本文档记录 **S5.1** 的三项增量，均为**用户实测反馈驱动**（"进到文档内部没有关联吗，还是没有做图谱"）。
> 日期：2026-09-13

## 1. 用户实测反馈 → 实证结论

用户提两个问题，实测后**结论与直觉相反**：

| 用户问题 | 实测结论 | 缺口 |
|---|---|---|
| 能否**关联索引到其他经验**（引用一条经验时） | ❌ 显式引用**不参与关联**；且全语料唯一 1 条链接是**误解析垃圾** | 需接入 + 修解析 |
| 颗粒度能否细化到**文档内条目** | ✅ **本来就是条目级**（`related.jsonl` 两端是 `docId#块号`，含同文档内条目互连） | **图谱只画文档节点**，条目级数据没有视图 |

### 1.1 关键实测数据（真实库）

```
related.jsonl 边两端形态（条目级，已验证）：
  experience/communication.md#0 → experience/workflow.md#48     (跨文档条目)
  experience/communication.md#0 → experience/communication.md#1 (同文档内条目)

links.jsonl：全库仅 1 行，且是垃圾：
  {"from":"experience/workflow.md","to":"'a','b'","target":null}
  来源：workflow.md 正文讲 JS 写法时写的  anyOf:[['a','b']]
  → wiki 链接正则 /\[\[([^\]|]+)(?:\|([^\]]+))?\]\]/ 把 **JS 嵌套数组当成了 [[wiki 引用]]**

getGraph：节点 kind='doc'，7 个；关联边被**聚合到文档对**
  → 真实库 74/76 条条目在 workflow.md **同一文件内** ⇒ 条目间 290 条关联在文档级
    **全部塌成自环被过滤** ⇒ `graph --related` 只剩 1 条跨文档边
```

即：**文档粒度的图谱对这个库几乎没有信息量**——这正是用户感觉"没有做图谱"的根因。

## 2. 本次范围（用户已定）

1. **图谱增「层级」开关**（文档 / 条目）
2. **显式引用接入为独立 `ref` 类型关联** + **修伪链接**

## 3. 变更 A：修伪链接（`extractLinks`）

**两道防护**（缺一不可，各自拦住不同的误判）：

1. **排除代码跨度**：匹配落在反引号（`` ` ``）内的跳过。
   依据：`anyOf:[['a','b']]` 出现在行内代码里；这是**通用**防护，
   能挡住未来各种"示例代码含 [[ ]]"（如文档里教人写 wiki 链接的段落）。
   实现：统计匹配位置之前的反引号数量，**奇数 = 位于代码内** → 跳过。
2. **目标形状校验**：wiki / md 链接的目标含 `'"()[]{}<>\s,;` 任一时跳过。
   依据：这些不是路径字符。`'a','b'` 含引号与逗号 → 被拦。

`extractLinks` 返回值增 `index`（匹配在原文中的字符下标），供变更 B 定位块。

## 4. 变更 B：`ref` 类型关联

### 4.1 links 记录增块定位

`links.jsonl` 每行增 `fromLine`（链接所在行号）与 `fromBlock`（该行所属块号，可空）：

- 定位方式：`extractLinks` 给的 `index` → 换算行号（数其之前的 `\n`）→
  在该文档块的 `[line, nextLine)` 区间里找所属块
- 定位不到 → `fromBlock = null`（不丢链接，只是退化为文档级）

### 4.2 ref 边生成规则

对每条 **`target` 非 null**（即 `resolveLinkTarget` 成功）的链接：

- **源**：`fromBlock`（单条条目）；`fromBlock` 为空时取**该文档的所有条目**
- **目标**：被引文档的条目，按 `cos(源条目, 目标条目)` 降序取前 `MAX_REF_RELATED`（**3**）
- `why = { kind: 'ref', to: '<被引文档 docId>', score }`
- `MAX_REF_RELATED=3` 的理由：`workflow.md` 有 57 条条目，引用整篇文档若不设上限会
  一次产生 57 条边（物化膨胀 + 挤占锚点预算）；按**内容相似度**取 top-3，
  "引用一篇文档时最相关的 3 条条目"才是真正值得继续读的

**`target` 为 null（断链/解析失败）→ 不产生任何 ref 边**。
这条同时是**修伪链接的兜底**：即便形状校验漏了某种伪链接，它也 resolve 不到真实文档 → 无边。

### 4.3 优先级与预算

锚点优先级：**tag（结构）× ref（手写意图）× content（派生）**。
三类**合计**受 `MAX_RELATED=8` 约束；`duplicate` 依旧**不占**预算（S5 §5.5）。
裁剪顺序：先保 tag，再保 ref，最后 content（手写意图优先于自动派生）。

### 4.4 可解释性

`why` 必须能展示：ref 边显示"引用：<被引文档标题>"+ 相似度（若按相似度选目标）。

### 4.5 读时校验

`validateRelation` 增 `ref` 分支：**只校验两端块存在**（+ 被引文档仍在）。

**不按内容指纹校验**，理由：引用是**用户手写的意图**，"这条经验引用了那篇文档"这件事
不因文档内容被编辑而失效；若按指纹校验，改一个字就会让引用锚点凭空消失，与用户预期相反。

### 4.6 与「反链」的关系（不混）

- **反链**（S2 既有）：**文档级**显式引用，回答"谁引用了我"，在 Inspector 单独一段
- **ref 关联**：**条目级**，回答"这条经验引用了哪篇文档的哪几条经验"，进「关联」段
- 两者**来源同一份 links、但粒度与用途不同** → GUI 仍分栏（S5 §4.1 的原则不破）

## 5. 变更 C：图谱「层级」开关

### 5.1 内核 `getGraph({ level })`

`level: 'doc'`（**默认**，行为与现状完全一致）/ `'entry'`：

- **entry 级节点**：`{ id: '<docId>#<n>', label: <条目摘要前 40 字>, docId, line, tag, kind:'entry' }`
- **entry 级边**：`related.jsonl` 的 **tag / content / ref** 三类（**排除 duplicate**）
- **显式链接边（doc→doc）不在条目级显示**：它是文档级关系，硬映射到条目会**造假**
  （链接不隶属某一条条目）。条目级的"引用"由 **ref 边**表达，语义更准。

### 5.2 GUI

- 顶部增**层级切换**（文档 / 条目），与既有「关联图层」开关并列
- 条目节点：label = 摘要前 40 字；点节点 → 打开该文档并**定位到该块**（用块 `line`）
- 三类边视觉可区分（禁裸 hex，全部走既有 token）：
  - 显式链接（文档级）：实线 + `--border-default`
  - tag 关联：细实线 + `--border-strong`
  - content 关联：虚线 + `--border-strong`（S5 既有）
  - ref 引用：点线（`strokeDasharray: '1 3'`）+ `--accent` 系
- 条目级节点较多（真实库 76 个）：`fitView` 后允许缩放；不额外做聚类（YAGNI）

## 7. 非目标（YAGNI）

- ❌ 不做条目级显式链接边（文档级关系硬映射=造假，见 §5.1）
- ❌ 不做条目级聚类/折叠（76 节点尚可读）
- ❌ 不做 ref 的反向"被引用"条目级视图（反链已有文档级）
- ❌ 不改 `MAX_RELATED` / 阈值 / idf 口径（S5 已校准，本次不动）
