> **任务分级**：`P1`-一般是大的功能升级和开发任务，需要具体细化spec并基于实际代码实现情况详细做plan，然后对照计划完成系统化开发；`P2`-一般是重要的维护或升级任务，需要与用户具体确认需求，形成spec，然后进行系统性的开发维护；`P3`-一般是小的细节调整任务，可不出spec，确定好修复点位后直接实施。

> ## 1. 目标
> 
> 每轮从清单中选择一个未完成、未阻塞、依赖已满足的任务，按质量要求执行。只有通过验证并满足完成定义，才允许把 `[ ]` 改为 `[x]`。
> 
> ## 2. 不可协商原则
> 
> - `[x]` 只代表“已验证完成”，不代表“已尝试”或“看起来完成”。
> 
> - 禁止伪造、猜测、夸大完成度，禁止伪造测试结果、日志、截图、证据。
> 
> - 不确定、缺权限、缺依赖、需求冲突时：不勾选，标记阻塞并说明。
> 
> - 一次循环只处理一个任务，除非明确允许批量。
> 
> - 不修改与任务无关的文件、配置、数据。
> 
> - 不删除、覆盖他人工作；破坏性操作必须先停止并请求确认。
> 
> - 遵守安全、隐私、权限和项目规范。
> 
> - 必须运行适用的质量门禁：`{测试 / lint / type / build / 格式化等}`。无法运行时，必须说明原因并给出替代验证。
> 
> ## 3. 任务选择顺序
> 
> 未勾选 → 未阻塞 → 依赖已满足 → 优先级高 → ID 小。  
> 若没有可执行任务，输出“无任务可执行”并结束本轮或循环。
> 
> ## 4. 完成定义 DoD
> 
> 任务只有同时满足以下条件才算完成：
> 
> 1. 满足任务描述与验收标准；
> 
> 2. 必要实现、测试、文档、迁移已完成；
> 
> 3. 质量门禁通过；
> 
> 4. 有可复查证据：命令、输出、diff、截图、日志、commit/PR；
> 
> 5. 无未解决阻塞；
> 
> 6. 变更最小，符合现有架构、风格和命名。
> 
> ## 5. 勾选规则
> 
> 满足 DoD 时：  
> `- [x] TASK-ID 描述 ✅ 完成时间：... 证据：... 验证：...`
> 
> 未满足时：  
> 保持 `- [ ]`，追加：`状态：进行中/阻塞/失败；原因：...；下一步：...`
> 
> 禁止在以下情况勾选：
> 
> - 测试未通过；
> 
> - 只写了代码但没有验证；
> 
> - 只完成一部分；
> 
> - 需要人类决策但未确认；
> 
> - 证据无法复查。
> 
> ## 6. 失败与阻塞
> 
> - 可修复错误：修复后重试，最多 `{N}` 次。
> 
> - 超过重试仍失败：标记失败，不勾选。
> 
> - 缺权限、依赖、需求：标记阻塞，写清需要谁提供什么。
> 
> - 高风险或破坏性操作：暂停并请求确认。
> 
> ## 7. 每轮循环协议
> 
> 每轮按顺序执行：
> 
> 1. 读行为准则；
> 
> 2. 读任务清单；
> 
> 3. 选任务并声明 DoD；
> 
> 4. 执行；
> 
> 5. 验证并收集证据；
> 
> 6. 按规则更新清单；
> 
> 7. 输出本轮摘要：任务、结果、证据、清单变更、下一轮建议；
> 
> 8. 结束循环前，做好系统整体代码审查，保证功能完整稳定，然后同步到调试版，给用户人工调试。

  - **根因（几何验算）**：会话行容器用的是 `.cut-sm`，切角由 `clip-path: polygon(8px 0, 100% 0, 100% calc(100% - 8px), calc(100% - 8px) 100%, 0 100%, 0 8px)` 实现，即**左上、右下各 8px 斜切**。而进度条 `.conv-progress` 是那个容器的**兄弟节点**（`bottom:2px; height:2px; left:4px; right:4px`），**不受 `clip-path` 裁切**，所以要靠自身内缩去避让切角。距底 2~4px 的高度区间里，右下斜边距右边只有 6~4px，原来的 `right:4px` 在底端会**伸出斜边约 2px** —— 与「进度条超出边缘范围」现象吻合。
  - **修法（最小改动，只动一个属性）**：`.conv-progress` 的 `right: 4px` → **`right: 8px`**（取切角尺寸作内缩量，该区间最紧处仍留 2px 余量）；左侧对应的是直角边，故 `left` 保持 4px 不变。改动处附了几何依据注释，避免后人再改回去。
  - **为何不是在容器上加 `overflow:hidden`**：那会把进度条这一层一起裁掉、并且影响容器内其它内容；本次问题只是"右侧多伸出 2px"，改内缩量是最贴题、影响面最小的做法。
