# P1 剩余重构方案（供评审，未实施）

范围：`server/bridge.mjs` 仍 3846 行。已完成的部分见 `docs/superpowers/specs/2026-09-17-bridge-fs-hardening-and-arch-cleanup-design.md` 的 §12（已迁出 9 组端点到 5 个路由模块）。

本方案的目标不是"把 bridge.mjs 拆小"，而是**按风险与收益排序，指出下一刀该切哪里、为什么，以及怎么验证**。

> 文中出现的**待新建**模块名一律不加反引号（仓库里还不存在），以免被文档口径检查误判为"引用不存在的路径"。

## 一、先修一个已确证的阻塞 bug（最高性价比，建议立刻做）

`/worktrees` 与 `/branches` 两个端点用 `execSync` 同步执行 git：

| 端点 | 现状 | 阻塞上限 |
|---|---|---|
| `/worktrees` | `execSync('git worktree list --porcelain', {timeout: 10000})` | 10s |
| `/branches` | `execSync('git branch -a …', {timeout: 10000})` | 10s |

桥是**单进程单事件循环**，同步执行期间**全部会话的 token 流与 WS 心跳停摆**。在大仓库上（分支数百、worktree 数个）耗时会上到秒级。

**这不是推测**：同类问题在 `/api/usage`、`/api/audit` 已经踩过并留下了实测数字——原 `execFileSync` 实测阻塞 **10.8–19.6s**，乘数是 transcript 文件数，后改为异步 spawn 才解决（见 `server/kernel-readonly.mjs`）。`/worktrees`、`/branches` 是同一个 bug 的未修版本。

**做法**：照搬 `server/kernel-readonly.mjs` 已有的异步 spawn 写法（同一类需求已有先例，不必新造）。改动约 30 行。

**验证**：加一条"并发探活"测试——在其一请求打 `/worktrees` 的同时，另一请求打 `/health` 并断言其延迟不被拖长（现有 `server/kernel-readonly-async.test.mjs` 就是按这个思路写的，可复用其结构）。

按"耦合面 ÷ 收益"排序。行号为当前 `server/bridge.mjs` 的位置。

| `/worktrees`、`/branches` | 2763–2841 | 79 | 去 execSync（见上节），**暂不迁文件** | 先修 bug，再谈搬家 |

理由：这些端点无状态、无会话耦合，且 host-routes 已建立同款约定（返回 `{status, body}` / `null`）。

| 区块 | 行范围 | 约行数 | 归属建议 |

### 明确**不做**的部分

- **核心转发区**（会话 spawn/转发、工具分发、内核 stdout 解析、审批与取消生命周期）：这是桥之所以是桥的部分，行数再多也不宜按端点切割。若要动，只能做**函数级抽离**（抽到同目录的纯函数模块、由 bridge import），并单独排期。
- **启动路径的同步 I/O**：`server/bridge.mjs` 仍有 `readFileSync` 19 处、`existsSync` 38 处等，但绝大多数在**启动/配置/技能安装**等一次性路径（微秒级、不在每次请求的热路径上）。上一轮已就此明确"刻意不做"，本方案维持该结论——**只修请求热路径上的同步 I/O**（即第一节那两处）。
- `taskkill` 的同步调用（取消/回收会话、端口自愈）：位于会话生命周期与启动自愈，语义上需要"立即生效"，保持同步更稳妥，不动。

## 三、每批的固定验证方式

所有批次共用同一套回归（不必每次重新设计）：

```bash
CI=true npm run test:preflight && node scripts/check-doc-anchors.mjs
CI=true npm run test:server      # 含端到端起桥测试（无 token 401、越界 403 等安全断言）
CI=true npm run test:kernel
npx tsc --noEmit
```

外加**该批特有**的验证点：

- 批次 1：并发探活（见第一节）。
- 批次 2：鉴权端点的**无令牌 401** 断言必须保持（现成的 `server/bridge-auth-token.test.mjs` 覆盖）。
- 批次 3：涉及写盘的端点要断言"未授权 POST 不产生写入"。

另：`docs/ci.md` 里记录的一个坑务必遵守——**不要把 5 条 glob 合成一次 `node --test` 并调高并发**，实测并发 8 时会出现两个假失败。分层串行是已验证的形态。

## 四、风险与回滚

- 每次只迁一组，迁完立刻跑上面四条命令；全绿再继续。
- 路由模块遵循既有约定（纯算响应、返回 `{status, body}` / `{stream}` / `null`），**不新造接口**——上一轮 `server/files-routes.mjs`、`server/office-routes.mjs` 已验证该约定的好处（可直测、不必起桥）。
- 迁移时**逐字保留**原异常策略。上一轮踩到的具体差异：`/tags*`、`/team/*` 是自带 try/catch 并如实回报 reason，而 `/file-collab/*` 不捕获、交由统一错误出口；用统一的 `.catch()` 会改掉前者语义。
- 回滚粒度就是单次提交，无需数据迁移（这些端点均无状态）。
