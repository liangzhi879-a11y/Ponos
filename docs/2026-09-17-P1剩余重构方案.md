## 一、先修一个已确证的阻塞 bug（✅ 已实施）

`/worktrees` 与 `/branches` 两个端点用 `execSync` 同步执行 git：

| 端点 | 原状 | 阻塞上限 |
|---|---|---|
| `/worktrees` | `execSync('git worktree list --porcelain', {timeout: 10000})` | 10s |
| `/branches` | `execSync('git branch -a …', {timeout: 10000})` | 10s |

桥是**单进程单事件循环**，同步执行期间**全部会话的 token 流与 WS 心跳停摆**。

**这不是推测**：同类问题在 `/api/usage`、`/api/audit` 已经踩过并留下了实测数字——原 `execFileSync` 实测阻塞 **10.8–19.6s**，乘数是 transcript 文件数，后改为异步 spawn 才解决（见 `server/kernel-readonly.mjs`）。`/worktrees`、`/branches` 是同一个 bug 的未修版本。

**实施方式**：新增 `server/git-async.mjs` 作为 git 异步调用的单一入口（`spawn` + 参数数组，非 shell），并补上 `execFileSync` 免费提供、而异步版必须自己实现的三道保险——timeout 到点即 kill、maxBuffer 超限即 kill、stderr 只留前 8KB。**不 kill 会比同步版更糟**（子进程挂死 → 路由永久悬挂）。

**验证**：新增 13 项测试。其中一条是"**调度不变量**"——git 子进程在飞时事件循环必须已获得调度机会（同步实现必然失败）。这条测试对本仓库后续任何"同步改异步"的改造都适用。

## 二、剩余区块清单与分批建议

按"耦合面 ÷ 收益"排序。行号为当前 `server/bridge.mjs` 的位置。

### 批次 1（低风险）✅ 已实施

| 区块 | 结果 |
|---|---|
| `/worktrees`、`/branches` | 已去 execSync（见上节），**端点留在 bridge**——先修 bug、再谈搬家 |
| `/health`、`/boot-status` | 已迁入 host-routes（两者都是"本应用自身运行状态"，同性质） |
| `/egress/policy` | 改归批次 2 的安全域（原计划放 host-routes，实为安全策略可观测面，依恋更合理） |
| `/sample-skills` | 改归批次 3 的 skills 域（与 `/skills`、`/install-skill`、`/uninstall-skill` 同批，不单独为 27 行开模块） |

**实施中的关键注意点**：`bootState` 是跨请求共享的**活对象**（boot 流程逐步置位），必须**按引用**传入 host-routes。传副本不会报错、端到端也可能通过，只是启动进度永远停在初始态——这类"静默失效"是本仓库拆分时踩过的坑，因此专门加了直测：**调用之后**对同一对象的改动必须能被下一次请求读到。

### 批次 2（中风险，一次一刀）✅ 已实施

| 区块 | 约行数 | 归属（实施后的实际归属） |
|---|---|---|
| `/api/auth/{status,setup,login,logout,change-password}` | 37 | ✅ `server/auth-routes.mjs` |
| `/api/profile`（GET/POST） | 21 | ✅ 同上（同属"身份面"） |
| `/session/anchor-applied` | 9 | ⛔ **改判：留在 bridge** —— 见下方"处置改判" |
| `/api/usage`、`/api/audit` | 43 | ✅ 单独成 `server/readonly-routes.mjs`（**不与 auth 混放**：一个是身份面、一个是只读聚合面，关注点不同） |

**处置改判（`/session/anchor-applied` 不搬）**：原计划把它塞进 auth 模块（只因都是 9 行的短小端点），实施时否掉了。它要 `buildAnchorApplied()` + `writeControlRequest()`——**后者是往内核 stdin 写控制请求**，属本方案开头就明确"不做"的**核心会话转发区**。为一个 9 行端点把会话控制依赖注入进"身份面"模块，换来的是语义混乱（auth 模块开始持有会话写口），不是内聚。**留在 bridge 更诚实**：它本来就在自己该在的地方。

**可行性复核结论**：原判断"真正需要按引用注入的只有 `authTokens`"——实施后更进一步：`authTokens` 与 `issueToken()` 在桥里**只被登录/登出用**（闸门用的是另一个静态 `BRIDGE_TOKEN`），故干脆**整体移入 auth 模块由它独占**，不再跨模块按引用注入。状态跟着它唯一的使用者走，比留在桥里再注入更不易出错（少一个可静默失效的注入点）。

**⚠️ 这一批有安全含义，动之前必须先确认两件事**（否则宁可不动）：

1. 鉴权端点必须落在**令牌闸门之后**（放闸门之前 = 未鉴权暴露）。搬运时确认委托点仍在闸门之后。
   **实施后的处置**：这条不再靠"人记得住"，而是**写成了断言**——`server/auth-routes.test.mjs` 与 `server/readonly-routes.test.mjs` 各有一条结构守卫，直接比对桥源码里
   `isAllowedOrigin(origin)` 白名单调用、`authorizeBridgeRequest(req, BRIDGE_TOKEN)` 闸门调用、`await handleAuthRoute({` / `await handleReadonlyRoute({` 委托点三者的字面位置。以后谁把委托点挪到闸门之前，测试即红。
   （守卫用**含实参的完整调用**做锚点，不用裸函数名——裸名会命中注释里提到的同名字符串，从而断言出一个虚假顺序；这是本仓库踩过的坑。）
2. 闸门由**两道**共同构成：`server/bridge.mjs` 开头的 `isAllowedOrigin(origin)` 白名单（外部来源一律 403，含预检）**在前**，`authorizeBridgeRequest()` 的令牌校验**在后**。第二道遇到"带非不透明 Origin"会直接放行——这在**两道合起来**时才安全（能走到第二道的 origin 已被第一道收窄到 null/file:/localhost）。
   **核查时务必读完整调用链**：只看第二道会觉得"任何来自 evil.com 的请求都免检"，是**误判**；实际在第一道已被 403。把 auth 端点搬走时若改变了两道之间的**先后顺序**，就会真的开出洞。
   **核查结果（已实测）**：两道顺序不变；且第二道的**豁免面是按 pathname 判定**、写在 `authorizeBridgeRequest` 内部（豁免含 `/health` 与 `/api/auth/*`，因为登录发生在拿到令牌之前）——**与"处理逻辑写在哪个文件"无关**。这正是本次搬迁安全的根据：路由搬走了，闸门判定照旧。

### 明确**不做**的部分

- **核心转发区**（会话 spawn/转发、工具分发、内核 stdout 解析、审批与取消生命周期）：这是桥之所以是桥的部分，行数再多也不宜按端点切割。若要动，只能做**函数级抽离**（抽到同目录的纯函数模块、由 bridge import），并单独排期。
- **启动路径的同步 I/O**：bridge.mjs 里 `readFileSync`/`existsSync` 等仍有数十处，但绝大多数在**启动/配置/技能安装**等一次性路径（微秒级、不在每次请求的热路径上）。上一轮已明确"刻意不做"，本方案维持该结论——**只修请求热路径上的同步 I/O**。
- `taskkill` 的同步调用（取消/回收会话、端口自愈）：位于会话生命周期与启动自愈，语义上需要"立即生效"，保持同步更稳妥。

## 四、风险与回滚

- 每次只迁一组，迁完立刻跑上面五条命令；全绿再继续。
- 路由模块遵循既有约定（纯算响应、返回 `{status, body}` / `{stream}` / `null`），**不新造接口**。
- 迁移时**逐字保留**原异常策略。踩过的具体差异：`/tags*`、`/team/*` 自带 try/catch 并如实回报 reason，而 `/file-collab/*` 不捕获、交由统一错误出口；用统一的 `.catch()` 会改掉前者语义。
- 回滚粒度就是单次提交，无需数据迁移（这些端点均无状态）。

**逐字保留的行为**（搬迁红线，改了就变契约）：
- `/api/profile` GET 的成功分支把文件内容**原样**作为响应体（不 `JSON.parse` 再 `stringify`）——后者会改变响应字节（键序、空白、以及非标准 JSON 时的容错差异）。为此给模块结果加了 `raw:true` 约定（调用方见到即直接发出、不再序列化），并在测试里用"含多余空白 + 非规范键序"的内容断言逐字一致。
- 只读聚合的 `computing → 503` / `failed → 502` 区分、以及三段原始设计注释（异步 spawn K2.1、TTL + stale-while-revalidate K2.2、503/502 语义）随代码一起搬到新模块——**那些注释是实现依据，不是冗余**。

**新增测试**：`server/auth-routes.test.mjs`（13 项：路径认领、档案读写的裁剪/递归建目录/超限拒绝/坏 JSON 退化、**raw 逐字透传**、**安全顺序守卫**）、`server/readonly-routes.test.mjs`（10 项：路径认领、query→flags 白名单拼装、空值跳过、未知参数不透传、`buildChildEnv` 每次重新求值、三态→状态码映射、**安全顺序守卫**）。
