## 合规红线（agent 执行前必读，违反即停止）

> **第一要求：严谨合规。所有资质数据必须来自官方政策原文，评分必须逐项可追溯，禁止编造任何申报条件。**

> ⚠️ **政策原文为准**：瞪羚企业为地方性资质（各省市/高新区自定标准），**分档阈值差异极大**。本技能内置条件为通用政策框架基准，**一切条件、分档阈值、评分标准必须与当年度申报地官方通知原文核对后采用**，并记录出处。

### 禁止事项（违反任何一条立即停止并告警）

1. **禁止编造申报条件**：复合增长率、研发占比、IP数量、信用评分等条件不得凭记忆或推断填写，必须与当年度当地官方通知核对（尤其注意分档口径）
2. **禁止编造增长率**：复合增长率必须基于审计报告逐年数据**真实计算**（CAGR公式），禁止用估算数据或人为选取基期
3. **禁止编造信用评分**：信用评分预评估必须引用官方信用查询结果（信用中国/地方信用平台/征信报告），不得估算
4. **禁止推断关键数据**：营收、研发费用、IP数量等字段必须以审计报告、所得税申报表、专利证书等官方文件为准
5. **禁止跳过脚本执行**：所有 `python C:/Users/T203-15/.yfworking/skills/_common/xxx.py` 命令必须通过 Bash 真正执行，不得"阅读脚本逻辑自行编写等效代码"
6. **禁止跳过审核步骤**：审核验证步骤必须执行且通过，未通过时不得继续后续步骤
7. **禁止自行兜底**：脚本报错时不得自行编写兜底代码，必须停止并告警由用户决定
8. **禁止跨技能污染**：仅读取当前项目留痕，不跨项目读取

### 数据来源优先级（高 → 低）

- **官方文件**（审计报告/所得税申报表/证书/当地官方通知原文）：✅ 可直接采用
- **官方信用平台**（信用中国/地方信用平台/征信报告）：✅ 用于信用评分，需截图存档
- **项目内数据**（企业提供的经营数据）：⚠️ 需与官方文件交叉验证后采用
- **缺失**：❌ 不得编造，必须标注"待补充"

### 无法确认时的处理

- **当年度当地官方通知未检索到**：停止申报流程，提示用户检索官方原文，禁止用其他城市旧版条件直接替代
- **增长率计算所需某年度审计报告缺失**：暂停计算，标注"待补充该年度审计报告"，禁止用估计值计算
- **信用查询失败**：暂停信用评分预评估，由用户通过人工渠道确认
- **脚本报错**：立即停止，输出错误日志，由用户决定修复方案
- **审核不通过**：停止后续步骤，输出 ERROR 清单，由用户决定整改方案

## 申报条件总览（通用框架基准，以当年度当地官方通知为准）

| 条件项 | 要求（通用框架） | 数据来源 |
|--------|-----------------|---------|
| 营收复合增长率 | 10%-25%，**按营收规模分档**（具体档位阈值以当地通知为准） | 近N年审计报告 |
| 研发投入占比 | 2.5%-5%，按规模分档 | 辅助账/所得税申报表 |
| 知识产权 | 发明专利≥2件，或实用新型+软著合计≥8件 | 专利证书 |
| 信用评分 | ≥75分 | 信用中国/征信报告 |
| 所属领域 | 战略性新兴产业/高新技术领域（多数地区要求） | 行业分类证明 |

**侧重差异（区别于高新认定）**：瞪羚评审**侧重增速而非存量**——成长性指标权重最高，存量研发规模权重较低。材料风格偏向**投融资视角**（资本追捧度、市场空间、商业模式验证、机构背书），而非高新认定的"研发体系完备性"视角。

## 工作流

### 第一步：项目初始化（强制执行，不可跳过）

```bash
python C:/Users/T203-15/.yfworking/skills/_common/project_context_manager.py init --enterprise "{企业名称}" --year {申报年份}
```

初始化后读取 file_map.json（文件分布）与 experience_base.json（历史经验）。

### 第二步：成长性指标计算与趋势图

1. 收集申报期及前N年（按当地通知确定基期）审计报告，提取逐年营收
2. 用 **CAGR 公式** 计算复合增长率：`CAGR = (期末营收 / 基期营收)^(1/n) - 1`，输出计算过程与数据来源
3. 按当地通知分档判定增长率达标档位
4. 生成《成长性趋势图》：逐年营收柱状图+增长率折线图（图表数据必须与审计报告逐笔对应）
5. 缺失某年度审计报告 → 暂停，标注"待补充"，禁止估计

### 第三步：创新能力评估

1. 统计有效期内知识产权：发明专利数量、实用新型数量、软著数量（复用 gxtz-ip-materials 数据）
2. 核对品类达标：发明专利≥2件，或实用新型+软著≥8件
3. 计算近三年研发投入占比（2.5%-5%分档核对），数据来源辅助账
4. 输出《创新能力评估表》：指标 → 数值 → 数据来源 → 达标状态

### 第四步：信用评分预评估

1. 查询官方信用平台（信用中国/当地信用平台/征信报告），截图存档
2. 按当地通知的信用评分口径逐项预评（经营异常/行政处罚/司法风险/纳税信用等）
3. 输出《信用评分预评估表》：评分项 → 查询结果 → 得分 → 证据文件
4. 查询失败或存在风险项 → 暂停确认，由用户决定处理方式

### 第五步：证明材料整理

- **复用部分（约50%）**：IP证书（gxtz-ip-materials）、财务数据（gxtz-core-tables TOAI表）、研发项目（gxtz-rd-report）
- **新增部分（约50%，投融资视角）**：逐年营收审计报告、增长率测算表与趋势图、融资记录/投资机构背书、客户增长与市场空间材料、信用查询结果
- 输出《材料清单》：每项标注"复用来源 / 新增需提供"

### 第六步：申报书撰写

1. 按当地官方申报书模板撰写，**成长性章节居首**（增速数据+趋势图+市场空间）
2. 叙述风格偏向投融资视角：突出增长逻辑、资本背书、商业模式验证，而非研发体系描述
3. 所有增长数据必须与第二步计算表一致，禁止口径漂移

### 最终步：审核验证（必须通过才能提交）

1. **条件审核**：增长率/研发占比/IP品类/信用评分全部达标
2. **计算审核**：CAGR计算过程复核，基期与口径与当地通知一致
3. **一致性审核**：趋势图数据、申报书数据与审计报告一致（逐年营收逐笔核对）
4. **政策原文审核**：分档阈值与当年度当地官方通知逐条核对一致
5. **文件审核**：调用命名规范检测（naming_compliance.py），PDF格式与大小合规
6. 生成《瞪羚申报审核报告》，输出 ERROR 清单或审核通过结论
