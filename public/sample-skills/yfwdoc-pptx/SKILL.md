# yfwdoc-pptx — 企业PPT/演示文稿制作

企业咨询场景的专业演示文稿制作技能，采用"受众锁定→内容框架→视觉排版"三阶段母版化方案，输出品牌合规、逐页质检通过的 .pptx。

## 3. 合规红线（不可逾越）

1. **禁止编造数据**：演示文稿中的业绩、财务数字、客户案例、荣誉资质必须来自用户提供的材料，缺失页禁止用编造或推测数据填充。
2. **禁止跳过人工审核闸门**：交付 .pptx 前必须用户过目确认；审核通过前禁止输出终版。
3. **禁止AI水印**：遵循 `C:/Users/T203-15/.ponos/skills/_common/SHARED_no_ai_watermark.md`，页面中禁止出现AI生成提示与示例占位。
4. **禁止使用未授权素材**：Logo、图片、图标、字体版权未确认前禁止使用（尤其网络下载素材）。
5. **禁止直接修改用户源文件**：原始素材只读，生成产物输出到独立目录。

## 4. 自主确认机制

遵循 `C:/Users/T203-15/.ponos/skills/_common/SHARED_autonomous_confirmation.md` 的5原则。PPT场景高发确认点：

| 触发类型 | 场景 | 处理 |
|---------|------|------|
| A 数据源冲突 | 同一业绩数字在用户多份材料中不一致 | 暂停，列出来源请用户指定 |
| B 格式异常 | 素材是扫描件/图片表格 | 先OCR（见 `SHARED_ocr_mandatory.md`），再提取数据 |
| C 关键推断 | 框架精简导致删除某内容页 | 说明删减方案，用户确认后才执行 |
| D 资料不完整 | 某页需要的数据/图片缺失 | 暂停，列缺失清单请用户补充 |

确认方式：先输出文本问题描述（含方案对比），再调用 AskUserQuestion，禁止默认执行。

## 5. 执行顺序契约

```
步骤1 确认受众和场景 → 步骤2 设计内容框架 → 步骤3 选择视觉风格
→ 步骤4 素材收集 → 步骤5 逐页生成 → 步骤6 整体质检 → 步骤7 审核闸门+输出
```

- 步骤2 大纲需用户确认后才进入生成

- 步骤7 用户确认前禁止交付终版

## 6. 工作流

### 步骤1：确认受众和场景（受众锁定）

**输入**：用户需求描述
**操作**：用 AskUserQuestion 锁定四个要素：
- **受众层级**：决策层（关注结论与投入产出）/ 业务层（关注方案细节）/ 外部客户（关注价值与案例）
- **场景**：项目路演 / 工作汇报 / 年终总结 / 培训 / 对外宣传
- **时长与场合**：按 1 分钟 1 页估算页数预算（如 10 分钟 ≈ 8-12 页）
- **已有素材**：数据文件、图文素材、历史版本PPT

**输出**：`{受众画像, 场景, 页数预算, 素材清单}`
**验证标准**：受众与场景缺失时必停确认，禁止自行假设（如默认"给领导汇报"）

### 步骤2：设计内容框架

**输入**：受众画像 + 场景 + 素材
**操作**：
- 生成页面骨架：封面 → 目录 → 总览/背景 → 分章内容（按场景组织：路演=痛点-方案-价值-案例；总结=成果-数据-问题-计划）→ 结论 → 致谢
- 每页写一句核心观点 + 支撑要点；数据页标注**数据来源文件**
- 向用户展示框架并等待确认

**输出**：`outline.md`（逐页大纲，每页含核心观点、要点、数据来源标注）
**验证标准**：用户确认大纲后才可进入下一步；大纲页数在预算内；数据页均有来源标注

### 步骤3：选择视觉风格（视觉排版）

**输入**：outline.md + 品牌素材
**操作**：
1. 查模板库：读 `C:/Users/T203-15/.ponos/skills/yfwdoc-template/_templates/template_index.json`，找企业PPT母版
2. 无现成母版 → 读 `brand_spec_*.json` 提取主题色/字体/Logo 现场构建母版（**主题色/Logo固化**：所有页面统一使用品牌色板与Logo，页脚统一企业名+页码）
3. 无品牌规范 → 询问用户（或建议先运行 yfwdoc-template 固化品牌）

**输出**：`{主题色HEX列表, 字体, Logo路径, 版式规范(16:9/页脚/间距)}`
**验证标准**：品牌规范缺失时必停询问，禁止随意选色充当企业品牌色

### 步骤4：素材收集

**输入**：outline.md + 视觉规范
**操作**：逐页核对素材齐备性：正文文字、数据（`doc_toolkit.py read` 提取）、图片、Logo、图标；素材缺失页标记记录
**输出**：素材齐备清单（每页：齐备/缺失/待替换）
**验证标准**：任何页存在缺失且无替代方案时暂停（D类），向用户列缺失清单；禁止用编造数据填充

### 步骤5：逐页生成

**输入**：大纲 + 视觉规范 + 素材
**操作**：用 python-pptx 脚本化逐页生成（16:9；封面/目录/内容/结尾页各用对应版式；每页页脚企业名+页码）。脚本骨架（agent 按素材实际生成后运行）：

```python
# gen_pptx.py —— 由 agent 生成并运行
from pptx import Presentation
from pptx.util import Inches, Pt
from pptx.dml.color import RGBColor

prs = Presentation()
prs.slide_width, prs.slide_height = Inches(13.333), Inches(7.5)
BRAND = RGBColor(0x1B, 0x4F, 0x9C)          # 品牌主色（来自 brand_spec）
LOGO = "C:/Users/T203-15/.ponos/skills/yfwdoc-template/_templates/assets/logo.png"
# 封面页：大标题 + 副标题 + 日期 + 企业Logo
# 目录页：outline.md 条目
# 内容页：标题 + 核心观点 + 要点列表 + 数据图表/图片（图表数据必须来自用户素材）
# 结尾页：结论 + 联系方式
# 每页统一页脚：企业名称 + 页码
prs.save("输出_路演_公司_20260804_v1.pptx")
```

- **HTML→PPTX转换**：素材为HTML/网页大纲时，先 `doc_toolkit.py read`（或直接读HTML文件）提取层级结构，映射为 标题→标题页、H2→章节页、列表→要点页，再按同骨架生成
- 每页只放一个核心观点，要点不超过5条；数据图优先用来源数据构造（matplotlib/原始图表）

**输出**：初版 .pptx
**验证标准**：页数=大纲页数；每页与 outline.md 一一对应；无空页/乱码/超出页面的文本框

### 步骤6：整体质检（VLM页面质检）

**输入**：初版 .pptx
**操作**：将各页渲染为图片，用 Read 工具逐页目检（VLM质检），检查：
- **结构质检**：页数一致、无空白页、无文字溢出/截断、层次清晰
- **视觉质检**：配色全部来自品牌色板、Logo清晰无变形、对比度达标、图文对齐一致、无模糊/拉伸图片
- **数据质检**：页面数字与来源文件逐项核对一致
- 发现问题记录到《质检问题清单》，修复后重新渲染复检

**输出**：《质检问题清单》（清零后交付）
**验证标准**：问题清单为空才可进入步骤7；数据页与来源文件不一致时暂停（A类冲突）

### 步骤7：人工审核闸门 + 输出

**输入**：质检通过的 .pptx + outline.md + 数据来源表
**操作**：
1. 输出《数据来源表》：列出每页引用数据及其来源文件，供用户复核
2. 将 pptx + 大纲 + 数据来源表交用户审核，等待明确回复
3. 用户确认后输出终版：`{用户指定目录}/{场景}_{标题}_{YYYYMMDD}.pptx`；如需打包 PDF 版同步导出（供只读传阅）

**输出**：终版 .pptx + 交付摘要（页数、风格、数据来源、待补充项）
**验证标准**：用户明确确认；交付摘要完整；用户确认前禁止声称交付完成
