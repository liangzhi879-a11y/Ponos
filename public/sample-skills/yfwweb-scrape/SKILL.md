## 合规红线（不可逾越，违反即终止本次操作）

| # | 红线 | 强制说明 |
|---|------|---------|
| 1 | **禁止抓取非授权网站** | 目标URL注册域名（eTLD+1）必须在域名白名单内；未列入白名单的域名一律拒绝访问，需用户明确授权后方可执行 |
| 2 | **禁止绕过验证码** | 遇到验证码/滑块/行为验证，立即暂停并告知用户，由用户人工完成；禁止 OCR 破解、模拟点击、逆向算法、第三方打码服务 |
| 3 | **禁止伪造身份** | 不伪造 Cookie/登录态、不冒用他人账号、不使用未授权账号、不冒充真人行为规避反爬（如模拟鼠标轨迹） |
| 4 | **禁止攻击系统** | 不进行高频并发请求、不利用漏洞、不抓取非公开数据、遵守站点 robots 约定与合理抓取频率 |
| 5 | **禁止敏感信息落盘** | 身份证号、手机号、银行账号等敏感字段一律脱敏后才可写入输出文件 |
| 6 | **禁止跨域跳转** | 页面重定向至白名单外域名时立即终止并告警 |
| 7 | **结果必须人工审核** | 抓取成果交付前必须由用户人工确认，不得直接作为申报材料使用 |

## 安全架构（全链路）

```
用户请求 → 域名白名单校验 → Playwright沙箱环境 → Accessibility Tree提取页面结构 → LLM决策下一步操作 → 人工闸门（提交/发送前确认）→ 操作日志+截图全链路存档
```

### 域名白名单
- **默认允许**：政府门户（`*.gov.cn`，含国家企业信用信息公示系统 gsxt.gov.cn）、省级/市级科技、工信、发改部门官网、行业主管部门公告栏。
- **校验规则**：以 eTLD+1 匹配白名单；每次 `page.goto` 前校验，重定向时复检。
- **扩展方式**：白名单外域名由用户明确授权后，加入本次会话白名单并记入审计日志。

### 沙箱隔离
- 所有操作在 Playwright 独立浏览器上下文中执行，与用户本机浏览器完全隔离。
- 不读取用户浏览器 Cookie / 密码 / 历史记录；登录态仅限用户主动提供的已授权账号。

### 日志审计
- 每步操作记录：时间戳、URL、动作、页面摘要、结果状态。
- 关键页面截图存档至输出目录 `screenshots/`，操作日志存 `logs/audit.log`。
- 审计日志与抓取成果一并交付，事后可完整追溯。

## 执行顺序契约

> 与 yfwweb-suite 总路由的协作顺序：

```
yfwweb-suite（总路由，按操作类型分派）
  ├─ 抓取/采集 → yfwweb-scrape（本技能）→ 格式化Excel → 人工审核
  ├─ 填报/填表 → yfwweb-form
  └─ 核验/查询 → yfwweb-verify
```

- 本技能输出（政策文件、公示数据、格式化Excel）可作为 **yfwweb-form** 的填表数据来源、**yfwweb-verify** 的比对基准。
- 跨技能传递数据时保留来源字段；数据不一致时注明来源差异，交由用户裁决，不得自行取舍。

## 工作流程（完整步骤）

### 步骤1：确认抓取目标与URL
- 与用户确认：目标网站URL、抓取范围（栏目/时间区间/关键词）、字段清单、输出格式（Excel/CSV/Markdown）。
- 生成任务清单：`{目标URL, 数据字段, 页数上限, 输出路径}`，向用户复述确认后才进入下一步。

### 步骤2：域名白名单校验
- 解析目标URL注册域名，与白名单比对。
- 不在白名单 → 暂停，说明原因，等用户授权（记入审计日志）。
- 在白名单 → 继续。

### 步骤3：浏览器导航
- 启动 Playwright 沙箱浏览器，`page.goto(url, timeout=30000)`，等待 `domcontentloaded`。
- 记录导航时间与HTTP状态；失败按"超时策略与失败回退"处理。

### 步骤4：页面结构分析（双模态）
- 提取 `page.accessibility.snapshot()` 获得 Accessibility Tree（结构化语义：标题/链接/表格/列表）。
- 同时 `page.screenshot()` 获得视觉信息（布局/样式/图表）。
- LLM 综合两模态输出页面结构摘要与候选数据节点定位。

### 步骤5：数据提取
- 按字段清单从 Accessibility Tree 定位数据节点，`page.locator()` 提取文本/属性/下载链接。
- 每个字段记录提取来源（选择器+页面URL），便于复核。

### 步骤6：分页/翻页自动处理
- 识别分页器（下一页按钮/页码列表/无限滚动），逐页提取。
- 每翻一页校验 URL 或内容变化，防止死循环；设页数上限（默认用户确认值）。
- 翻页失败超过3次 → 按自愈机制处理。

### 步骤7：自愈重试（最多20次）
- 页面结构变化导致定位失败时，自动触发自愈：重新提取 Accessibility Tree → LLM重新分析 → 更新定位策略。
- 自愈阈值：单页内最多20次；耗尽后暂停并展示当前状态，请用户人工干预。

### 步骤8：格式化输出
- 用 `python doc_toolkit.py info --file <模板>` 查表后，以 openpyxl 写入 Excel：数据列 + 来源URL列 + 抓取时间列。
- 敏感字段按脱敏规则处理后再写入。
- 输出文件命名：`{主题}_抓取_{YYYYMMDD}.xlsx`，存至用户指定的输出目录。

### 步骤9：人工审核
- 向用户交付：成果文件 + 审计日志路径 + 截图目录 + 数据抽样预览（前10条）。
- 用户确认通过后才算完成；用户指出问题则回到对应步骤修正。

## 超时策略与失败回退

| 层级 | 策略 |
|------|------|
| 导航超时 | `goto` 30秒，`domcontentloaded` 15秒 |
| 单页操作预算 | 每页提取+翻页总时长60秒，超时记失败 |
| 重试退避 | 连续失败最多重试3次，间隔 2s/4s/8s 指数退避 |
| 自愈重试 | 页面结构变化时重新分析定位，最多20次 |
| 最终回退 | 连续失败 → 保存已提取数据与当前截图 → 暂停告知用户，由用户决定继续/跳过/人工处理 |

## 数据输出规范

- 表格首列必须含"来源URL"，末列"抓取时间"，保证数据可溯源。
- 下载类文件（政策PDF/附件）保存在 `downloads/` 子目录，文件名保持原始名称并加前缀防重名。
- 禁止将抓取内容直接写入申报材料；一切成果须经步骤9人工审核。
