## 合规红线（agent 执行前必读，违反即停止）

> **第一要求：严谨合规。所有数据必须真实可溯源，禁止任何形式的编造。**

### 禁止事项（违反任何一条立即停止并告警）

1. **禁止编造PS名称**：PS名称必须从历史申报材料（高新申报书）中提取，不得从发票货物名称反推
2. **禁止跳过申请书读取**：第一步必须读取申请书提取PS基线，不可跳过直接从发票开始
3. **禁止自行决定PS范围**：申请书PS与发票不匹配时，必须暂停确认，不得自行扩展或取消PS
4. **禁止跳过脚本执行**：所有 `python {{YFW_SKILLS}}/_common/xxx.py` 命令必须通过 Bash 真正执行
5. **禁止跳过审核步骤**：审核验证步骤必须执行且通过，未通过时不得继续后续步骤
6. **禁止自行兜底**：脚本报错时不得自行编写兜底代码，必须停止并告警由用户决定
7. **禁止跨技能污染**：仅读取当前项目留痕，不跨项目读取；技能内步骤使用当前技能定义的脚本，蜂群编排层可调用_common公共脚本做协调

### PS名称来源优先级（高 → 低）

1. **上次高新申报书中的PS名称** → ✅ 直接使用（权威来源）
2. **申报书PS名称 + 技术方向扩展** → ⚠️ 保持延续性，适度扩展（需用户确认）
3. **全新PS名称** → ❌ 仅在前两者确实无法覆盖时使用（需用户确认）

### 无法确认时的处理

- **申请书PS无对应发票**：暂停，询问用户是否取消该PS
- **发票收入无法匹配申请书PS**：暂停，询问用户是否需要扩展PS命名
- **高新收入占比可能不达标**：暂停，询问用户是否需要扩展PS范围
- **脚本报错**：立即停止，输出错误日志，由用户决定修复方案

## 描述

全量发票PS筛选技能，用于RDPS表格生成阶段确定PS范围。

**核心原则**：PS名称必须从历史申报材料（高新申报书）中提取，而非从发票货物名称反推。只有历史PS与当前发票无法匹配时，才进行扩展优化。

**工作流程**：从申请书提取PS基线 → 读取全量发票 → 匹配 → 自主确认 → 扩展优化 → 生成标注文件

## 输入输出

- **输入**：
  - 高新申报书PDF（含PS表格）
  - 上年度全量发票导出结果Excel（含发票号码、开票日期、购方名称、货物名称、价税合计等）
- **输出**：
  - PS发票标注表.xlsx（每个PS一个Sheet，含发票明细）
  - PS统计表.xlsx（PS编号/名称/发票数量/金额合计/占比）
  - 占比分析报告.json（高新收入占比/是否达标60%）

## PS扩展命名桥接策略（v1.2.0新增，基于友联普达项目经验）

> **适用场景**：贸易品占比过大（如电机83%收入），但纯贸易品名称（"永磁同步电机"）无法与任何RD的关键词匹配时。

### 桥接策略核心思路

```
贸易品名称 → 找到其核心组件中的研发部分 → 重新定义为"研发组件+贸易品"的组合名称
```

**项目案例**（友联普达）：

| 维度 | 修复前 | 修复后 |
|------|--------|--------|
| PS名称 | 永磁同步电机 | 驱动控制与执行模组 |
| 关键词 | 电机/马达（电路板RD零匹配） | 驱动/控制/电源/功率器件 |
| 匹配结果 | 0 RD关联 | 匹配到多个电路板RD |
| 逻辑依据 | 无 | 核心研发是驱动控制电路板，外购电机作为执行组件 |

### 可用桥接词库

```
电子电路类：驱动控制 / 电源管理 / 功率器件 / 信号处理 / 嵌入式系统 / 控制器 / 模组
机械结构类：精密结构件 / 传动系统 / 执行组件 / 壳体总成 / 散热模组
软件系统类：控制软件 / 算法平台 / 数据分析系统 / 管理平台
```

### 操作步骤

```
1. 识别：贸易品PS无法匹配到任何RD（匹配数为0）
2. 分析：该PS中企业实际研发了什么？（不是生产了什么）
3. 桥接：用研发组件词+贸易品词组成新PS名称
4. 验证：新PS名称下的桥接词能否匹配到RD表
5. 确认：确认新名称在技术上合理（非虚构），输出调整记录
```

> **红线**：PS名称不能凭空自创。重新定义的PS名称必须有技术依据，且调整记录需在最终审核报告中体现。

## 占比分母硬性规则（v1.2.0新增，基于友联普达项目经验）

> **已犯错误**：用"已匹配PS合计金额"做分母计算高新收入占比——这会导致占比虚高。

### 正确规则

```python
# ❌ 错误：分母用已匹配PS合计
ratio = matched_ps_total / matched_ps_total  # 永远=100%

# ✅ 正确：分母必须是全量发票总金额
ratio = matched_ps_total / all_invoice_total
```

| 分母 | 含义 | 用途 |
|:---:|------|------|
| **全量发票总金额** | 所有发票的价税合计（不论是否匹配到PS） | 高新收入占比计算的分母 |
| 已匹配PS合计金额 | 仅已匹配到PS的发票金额 | 高新收入合计（分子） |

**强制校验**：占比分析报告必须验证 `分母 = sum(全量发票.价税合计)`，与 `发票明细.json` 中的 `total_amount` 一致。

```
│ 第七步：生成标注文件 + 统计表 + 占比分析           │
│ → 每个PS独立颜色标注                             │
│ → 金额合计、价税合计、占比                       │
│ → 高新收入占全量发票比例                          │
└─────────────────────────────────────────────────┘
```

## 输出隐患自查与汇报（v1.4.0升级，技能结束时强制执行）

> **强制要求**：完成发票PS筛选后，agent 必须按以下7个维度进行隐患自查并汇报。

### 自查清单（7维覆盖）

| 维度 | 检查项 | 表现 |
|------|------|------|
| **1. 原始资料缺失** | 全量发票Excel文件是否存在 | 发票数据源文件缺失 |
| | 历史申报材料（高新申报书）是否可读取 | 无法提取PS基线名称 |
| | 发票明细中的附件/图片是否齐全 | 发票扫描件缺失 |
| **2. 文本质量** | PS技术说明中的关键技术描述是否有实质内容 | 套话无具体技术参数 |
| | 发票货物名称与PS名称的匹配是否合理 | 强行匹配，语义不相关 |
| **3. 逻辑关联** | 占比分母是否=全量发票总金额（非已匹配PS合计） | 分母计算错误 |
| | 未匹配发票数量及金额是否合理 | 未匹配发票占比过大（>30%）需说明原因 |
| | 每个PS是否有足够的发票支撑 | PS匹配发票数过少 |
| | 高收入占比PS是否有对应的RD/IP支撑 | 高收入PS无研发支撑 |
| **4. 字数问题** | PS技术说明字数是否满足报表要求 | 技术说明字数不足 |
| **5. 文档格式** | 发票明细Excel格式是否规范 | 列名混乱、日期格式不一致 |
| | 标注文件（标注发票归属PS的文件）是否清晰可读 | 标注不清晰 |
| | 统计报表格式是否符合模板要求 | 表头/列序与模板不符 |
| **6. 政策符合性** | PS名称是否从申请书提取（非自创/反推） | PS名称非申请书来源 |
| | 高新产品收入占总收入比例≥60% | 高新收入占比不达标 |
| | 发票中的产品品类是否在高新八大领域内 | 存在非高新领域产品 |
| **7. 数据可溯源性** | 每张发票的PS标注可否追溯到匹配规则 | 匹配规则不透明 |
| | 占比计算可否追溯到原始发票明细 | 中间计算结果无处可查 |
| | 未匹配发票是否保留了完整的原始记录 | 未匹配发票被丢弃未记录 |

### 汇报格式

```
⚠️ gxtz-invoice-ps-matching 输出隐患自查报告

1. 原始资料: ✓ / ⚠ {n}项缺失
2. 文本质量: ✓ / ⚠ {n}处需优化
3. 逻辑关联: ✓ / ⚠ {n}个隐患
4. 字数: ✓ / ⚠ {n}字段需补充
5. 文档格式: ✓ / ⚠ {n}处不规范
6. 政策符合性: ✓ / ⚠ {n}项不合规
7. 数据溯源: ✓ / ⚠ {n}字段无来源

PS匹配汇总：{PS名称} {n}张发票 {x}万元
未匹配：{n}张发票 {x}万元（占比{y}%）

待用户确认后进入下一步。
```
