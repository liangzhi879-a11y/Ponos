# 变更日志模板

> 每个技能的 CHANGELOG.md 需遵循本模板，确保经验→技能升级闭环可追溯。

## 模板格式

```markdown
# 变更日志

### v{版本号} - {日期}

**{变更标题}**

触发源经验（待消费经验清单回应）：
- {EXP-ID}「{经验问题描述}」✅ 已回应
  → 解决：{本版本如何解决该经验}
- {EXP-ID}「{经验问题描述}」⏳ 部分回应
  → 解决：{本版本部分解决，剩余待后续版本}
- 无待消费经验（本次为主动优化）

变更内容：
1. {具体变更项1}
2. {具体变更项2}
3. {具体变更项3}

涉及文件：
- {文件1}（{修改说明}）
- {文件2}（{修改说明}）

验证结果：
- ✅ {验证场景1}：{结果}
- ✅ {验证场景2}：{结果}
- ⏳ {待验证场景}：{说明}

经验状态更新：
- {EXP-ID}：pending → consumed（已消费，待验证）
- {EXP-ID}：consumed → verified（验证通过）
- {EXP-ID}：consumed → failed（验证失败，回退pending）
```

## 示例（gxtz-core-tables v1.18.2）

```markdown
### v1.18.2 - 2026-07-14

**IP表软著摘要字段规则强化**

触发源经验（待消费经验清单回应）：
- EXP-2026-07-13-001「IP表软著摘要字段为空」✅ 已回应
  → 解决：SKILL.md统一规则 + validate_tables.py新增校验 + 预处理自动填"无"

变更内容：
1. SKILL.md 统一软著摘要字段规则：软件著作权摘要必须填"无"（禁止空值，禁止填其他内容）
2. validate_tables.py 新增校验规则：软著行摘要为空报错；非"无"警告
3. generate_tables_from_template.py 新增软著摘要预处理：为空时自动填"无"

涉及文件：
- SKILL.md（6处修改）
- _common/validate_tables.py（TABLE_SPECS + 校验逻辑）
- _common/generate_tables_from_template.py（新增预处理逻辑）

验证结果：
- ✅ 场景1：空软著摘要 → 自动填"无"
- ✅ 场景2：非空专利摘要 → 保留原文
- ⏳ 待验证：宏日嘉项目端到端测试

经验状态更新：
- EXP-2026-07-13-001：pending → consumed（已消费，待验证）
```

## 规则

1. **每次技能升级必须包含"触发源经验"章节**：即使是主动优化，也需标注"无待消费经验"
2. **每条待消费经验必须逐条回应**：✅已回应 / ⏳部分回应 / ❌未回应
3. **验证结果必须列出验证场景**：✅通过 / ⏳待验证 / ❌失败
4. **经验状态更新必须标注**：从哪个状态转到哪个状态
5. **禁止**：跳过"触发源经验"章节；未回应待消费经验即提交
