## 合规红线（agent 执行前必读，违反即停止）

> **第一要求：严谨合规。所有资质数据必须来自官方政策原文，评分必须逐项可追溯，禁止编造任何申报条件。**

> ⚠️ **政策原文为准**：专精特新认定每年申报条件可能微调（工信部及各省市通知口径存在差异）。本技能内置条件为政策框架基准，**一切条件、分值、材料要求必须与当年度当地官方通知原文核对后采用**，并记录出处。

### 禁止事项（违反任何一条立即停止并告警）

1. **禁止编造申报条件**：营收、主营占比、研发投入、IP数量、评价得分等条件不得凭记忆或推断填写，必须与当年度官方通知核对
2. **禁止编造评分结果**：四化指标自评每个得分项必须列明得分依据、数据来源与计算过程；无法取得数据的分项填"待补充"，不得估分
3. **禁止编造市场数据**：细分市场占有率、产业链配套地位等表述必须有权威来源（行业协会报告/上市公司公告/券商研报/招股书/官方统计数据），禁止用客户口头估算直接写入
4. **禁止推断关键数据**：营收、主营收入占比、研发费用、知识产权等字段必须以审计报告、所得税申报表、专利证书等官方文件为准
5. **禁止跳过脚本执行**：所有 `python C:/Users/T203-15/.yfworking/skills/_common/xxx.py` 命令必须通过 Bash 真正执行，不得"阅读脚本逻辑自行编写等效代码"
6. **禁止跳过审核步骤**：审核验证步骤必须执行且通过，未通过时不得继续后续步骤
7. **禁止自行兜底**：脚本报错时不得自行编写兜底代码，必须停止并告警由用户决定
8. **禁止跨技能污染**：仅读取当前项目留痕，不跨项目读取

### 数据来源优先级（高 → 低）

- **官方文件**（审计报告/所得税申报表/证书/官方通知原文）：✅ 可直接采用
- **权威第三方数据**（行业协会/研报/招股书）：⚠️ 需标注来源与报告日期后采用
- **项目内数据**（企业提供的经营数据）：⚠️ 需与官方文件交叉验证后采用
- **缺失**：❌ 不得编造，必须标注"待补充"

### 无法确认时的处理

- **当年度官方通知未检索到**：停止申报流程，提示用户提供或协助检索官方原文，禁止用旧版条件直接替代
- **细分市场占有率无法佐证**：标注"待补充（需提供行业协会/研报证明）"，不得估算
- **脚本报错**：立即停止，输出错误日志，由用户决定修复方案
- **审核不通过**：停止后续步骤，输出 ERROR 清单，由用户决定整改方案

## 执行顺序契约（agent 必须严格遵守）

### 执行原则

1. **顺序执行**：必须按第一步 → 第二步 → ... → 最后一步顺序执行，严禁跳过任何步骤
2. **失败即停**：任何步骤失败（脚本报错、校验不通过、数据缺失）立即停止，输出错误信息，不得继续
3. **不可并行（有依赖时）**：技能内步骤有数据依赖时不得并行；跨技能独立任务在蜂群编排下可并行执行，参见蜂群编排规范（_swarm_orchestration.md）
4. **不可跳过审核**：审核验证步骤必须执行且通过，未通过时不得进入下一步

### 步骤编号规则

- **第一步**：项目初始化（强制执行，不可跳过）
- **第二步 ~ 倒数第二步**：核心业务步骤
- **最后一步**：审核验证（必须通过才能提交）

### 失败处理标准流程

1. **立即停止**当前步骤及后续所有步骤
2. **输出错误信息**：包含失败步骤、错误原因、脚本日志（如有）
3. **输出已完成的步骤清单**：让用户了解当前进度
4. **等待用户决定**：由用户决定修复方案（核对政策原文/补充资料/手工处理）
5. **禁止自行兜底**：不得"阅读脚本逻辑自行编写等效代码"

## 申报条件总览（政策框架基准，以当年度官方通知为准）

| 条件项 | 要求 | 数据来源 |
|--------|------|---------|
| 前置条件 | 创新型中小企业（已入库或同时申报） | 工信部门公示名单 |
| 营业收入 | ≥1500万元（部分地区另有更高分档要求） | 审计报告 |
| 主营业务收入占比 | ≥80% | 审计报告/科目明细 |
| 研发投入 | ≥100万元/年，且占营业收入比例≥3% | 辅助账/所得税申报表 |
| Ⅰ类知识产权 | ≥1项（有效期内） | 专利证书 |
| 评价得分 | ≥50分（专业化/精细化/特色化/新颖化四档赋分） | 自评打分表 |

**核心证明材料（本技能新增，约30%工作量）**：
1. **四化特征证明材料**：专业化（主导产品/产业链配套）、精细化（管理体系认证/质量/数字化）、特色化（特色工艺/独特技术/地方特色资源）、新颖化（研发创新/IP/新产品）逐项撰写
2. **细分市场占有率证明**：细分领域界定 → 市场容量数据 → 企业份额测算 → 第三方佐证
3. **产业链配套证明**：与下游大企业合作合同/供应商资质/配套产品清单

## 工作流

### 第一步：项目初始化（强制执行，不可跳过）

```bash
python C:/Users/T203-15/.yfworking/skills/_common/project_context_manager.py init --enterprise "{企业名称}" --year {申报年份}
```

初始化后读取 file_map.json（文件分布）与 experience_base.json（历史经验）。

### 第二步：前置条件确认

1. 核对企业在"创新型中小企业"公示名单中的状态（在库有效/在评/无）
2. 不在库且未申报 → 暂停，提示用户：专精特新必须以创新型中小企业为前置，需先完成创新型中小企业申报
3. 输出《前置条件确认表》

### 第三步：自评打分（可追溯）

按四化指标逐项打分（≥50分），每项记录得分依据：

| 四化指标 | 满分 | 得分 | 得分依据（数据来源） |
|----------|------|------|---------------------|
| 专业化 | ? | ? | 主营占比+细分领域专注度 |
| 精细化 | ? | ? | 管理体系认证/质量体系 |
| 特色化 | ? | ? | 特色工艺/独特技术 |
| 新颖化 | ? | ? | 研发投入/IP数量 |
| **合计** | **100** | ? | 必须≥50分 |

### 第四步：四化特征提炼

1. 从企业产品/技术资料中提炼四大特征关键词与支撑事实
2. 每个特征必须对应**可核验的证明材料**（证书/合同/报告），禁止抽象化表述
3. 输出《四化特征提炼表》：特征 → 支撑事实 → 对应证明文件 → 撰写要点

### 第五步：证明材料整理（70%复用高新 + 30%新增）

- **复用部分（约70%）**：IP证书（gxtz-ip-materials）、人员材料（gxtz-staff-materials）、RD项目（gxtz-core-tables/gxtz-rd-report）、财务数据、管理制度材料（gxtz-management-materials）
- **新增部分（约30%）**：细分市场占有率证明、产业链配套证明、四化特征专项佐证（认证证书/荣誉/独有工艺证明）
- 输出《材料复用映射表》：每项申报材料标注"复用来源 / 新增需提供"

### 第六步：申报书撰写

1. 按官方申报书模板逐章撰写（企业基本情况/四化特征/创新投入/市场地位）
2. 数据必须引用第五步材料清单中的真实文件，标注引用来源
3. 市场占有率、产业链地位表述附第三方佐证来源说明

### 第七步：审核提交

1. 按官方通知确认受理渠道（省级/市级工信部门平台）与时间窗口
2. 提交前对照《申报材料清单》逐项核对完整性
3. 输出《提交前检查单》交用户确认后提交

### 最终步：审核验证（必须通过才能提交）

1. **条件审核**：全部硬指标达标（前置/营收/主营占比/研发投入/IP/评分）
2. **评分审核**：自评得分≥50分，每个得分项均有数据来源
3. **真实性审核**：市场占有率、产业链地位表述均有权威来源；四化特征均有证明文件
4. **一致性审核**：复用材料与企业高新申报文件数据一致（营收/人数/IP编号）
5. **政策原文审核**：所有条件与当年度官方通知原文逐条核对一致
6. **文件审核**：调用命名规范检测（naming_compliance.py），PDF格式与大小合规
7. 生成《专精特新申报审核报告》，输出 ERROR 清单或审核通过结论
