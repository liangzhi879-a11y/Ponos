## 3. 合规红线（不可逾越）

1. **禁止硬编码计算值**：分析结果必须保留公式（SUM/AVERAGEIF/SUMIF等）由Excel计算，禁止把算好的数值当静态值写入。
2. **禁止编造数据**：任何统计口径（汇总/同比/占比/透视）必须与源数据一致且可复核；源数据本身缺失时暂停询问。
3. **源文件只读**：不修改用户原始Excel，分析产物一律输出新文件。
4. **推断性操作先确认**：缺失值填充、费用分摊、口径归并等含推断性质的处理，先说明方法与影响再执行。
5. **敏感数据提示**：含个人/财务敏感信息时提醒用户脱敏范围后再输出。
6. **大文件优化**：>50MB 文件仅读取所需 Sheet/列，禁止整表载入导致卡死；处理前先说明优化策略。

## 4. 自主确认机制

遵循 `C:/Users/T203-15/.yfworking/skills/_common/SHARED_autonomous_confirmation.md` 的5原则。Excel场景高发确认点：

| 触发类型 | 场景 | 处理 |
|---------|------|------|
| A 数据源冲突 | 同一指标在多Sheet/多来源文件中数值不一致 | 暂停，列出各来源数值请用户指定基准 |
| B 格式异常 | 日期/数字被存成文本、合并单元格、隐藏行列 | 说明清洗方案（如转换类型），确认后执行 |
| C 关键推断 | 缺失值按均值填充、费用按比例分摊到月份 | 说明推断依据与偏差影响，用户确认后才执行 |
| D 资料不完整 | 关键列缺失、无关联键可join | 暂停，列缺失清单请用户补充 |

确认方式：先输出文本问题描述（含方案对比），再调用 AskUserQuestion。

## 5. 执行顺序契约

```
步骤1 读取数据 → 步骤2 理解需求 → 步骤3 数据清洗 → 步骤4 分析计算
→ 步骤5 生成报表+图表 → 步骤6 输出.xlsx + HTML看板
```

- 步骤2 的需求单（口径/指标）必须用户确认后才开始计算
- 步骤3 清洗规则需逐条可追溯；含推断性清洗先确认
- 步骤4 每个关键指标必须与源数据交叉验证一致后才进入步骤5

## 6. 工作流

### 步骤1：读取数据

**输入**：用户提供的Excel文件路径
**操作**：
```bash
python "C:/Users/T203-15/.yfworking/skills/_common/doc_toolkit.py" info --file "<文件路径>"
python "C:/Users/T203-15/.yfworking/skills/_common/doc_toolkit.py" read --file "<文件路径>" --format xlsx --max-rows 500
```
.xls 旧版先 `convert --to xlsx`。多文件/多Sheet时逐个读取并记录结构。

**输出**：`{Sheet清单, 各Sheet列结构, 数据样本, 行数, 数据量}` 
**验证标准**：全部Sheet已识别；Sheet数量多时输出索引表请用户圈定分析范围（禁止全量猜范围）

### 步骤2：理解需求

**输入**：数据结构 + 用户需求
**操作**：用清单式提问收集：
- **分析目标**：要回答什么问题（趋势/占比/对比/异常）
- **统计口径**：时间范围、汇总维度（按客户/产品/月份/项目）、是否含税、是否含删除项
- **输出形式**：汇总报表 / 明细+汇总 / 图表 / HTML看板 / 全部
- **受众**：内部决策 or 对外交付

**输出**：《分析需求单》（目标/口径/指标清单/输出形式，逐项用户确认）
**验证标准**：口径不明（如"销售额"含不含税、统计范围到几号）必停确认；需求单确认后才可进入清洗与计算

### 步骤3：数据清洗

**输入**：需求单 + 原始数据
**操作**：
- **格式统一**：日期/数值/文本类型转换（记录转换规则）
- **空值处理**：统计缺失率，处理方式（删除/保留/填充）列清单由用户确认
- **去重**：按关联键去重，记录去重前后行数与规则
- **多Sheet关联**：确认关联键（订单号/客户ID/项目名等），核对两表键值一致性；键缺失/多对多时暂停
- 清洗结果与规则写入《清洗报告》，保证可追溯

**输出**：《清洗报告》（每类处理：规则、影响行数、示例）+ 清洗后数据
**验证标准**：清洗规则全部有记录；推断性清洗（填充/分摊）已获用户确认；关联键无二义

### 步骤4：分析计算

**输入**：清洗后数据 + 需求单
**操作**：
- 用公式实现所有汇总指标：SUMIF/COUNTIF/AVERAGEIF/IF组合写入计算列/汇总表（**公式而非静态值**）
- **数据透视表自动生成**：openpyxl PivotTable（行/列/值字段按需求单配置，值字段用求和/计数/平均）
- **交叉验证**：每个关键指标与源数据明细对账（如"总营收 = 各Sheet合计 = 透视表总计"），对不上立即排查

**输出**：带公式的计算Sheet + 透视表Sheet
**验证标准**：关键指标全部可复核（对账通过）；Sheet内为公式引用而非硬编码数值；任一指标对账失败时暂停排查，禁止带错交付

### 步骤5：生成报表+图表

**输入**：计算结果
**操作**：
- **报表**：汇总表+明细表分层组织，命名/配色遵循企业品牌规范（读 `yfwdoc-template` 的 `brand_spec_*.json`，无规范用中性配色）
- **图表**：按数据性质选型——趋势用折线、对比用柱状、占比用饼图；图表带标题、单位、图例、数据标签；图表数据区间直接引用汇总Sheet
- **条件格式**：关键阈值高亮（超预算红、达标绿、异常黄），规则在《交付摘要》中说明

**输出**：`报表_{主题}_{YYYYMMDD}.xlsx`（含透视、图表、条件格式）
**验证标准**：图表引用区间与汇总Sheet一致；无断裂引用/空图表；条件格式阈值经用户确认过

### 步骤6：输出 .xlsx + HTML看板

**输入**：报表.xlsx
**操作**：
- 输出终版：`{用户指定目录}/{主题}_报表_{YYYYMMDD}.xlsx`
- 生成 `{主题}_看板_{YYYYMMDD}.html`：纯静态HTML（数据内嵌+图表渲染，双击即开），看板指标与xlsx数值逐一一致
- 大文件优化检查：产物>10MB时提示用户是否需要裁剪明细/压缩图片；>50MB禁止整体重读，仅追加所需块
- 输出《交付摘要》：统计口径、清洗记录、指标定义、图表说明、待确认项

**输出**：.xlsx + HTML看板 + 交付摘要
**验证标准**：交付物打开正常；看板与xlsx数字完全一致（抽查≥3个关键指标）；口径经用户确认；敏感数据按确认范围输出
