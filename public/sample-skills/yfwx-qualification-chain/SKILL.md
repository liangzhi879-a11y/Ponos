## 合规红线（agent 执行前必读，违反即停止）

> **第一要求：严谨合规。所有资质数据必须来自官方政策原文，匹配结论必须逐项可追溯，禁止编造任何申报条件。**

> ⚠️ **政策原文为准**：本技能内置的资质条件库为政策框架基准，每年均有微调、各地口径不一。**所有匹配结论必须标注政策依据版本**，当年度官方通知发布后必须以最新通知校准条件库，禁止沿用旧版条件输出结论。

### 禁止事项（违反任何一条立即停止并告警）

1. **禁止编造申报条件**：任何资质的营收/人数/IP/研发/年限/评分条件不得凭记忆或推断填写，必须逐条标注政策依据
2. **禁止编造匹配结论**：每个"可申报/条件接近/暂不符合"结论必须有数据依据与计算过程，可追溯；基础数据缺失时填"待补充"并暂停该资质评估
3. **禁止编造补贴金额**：投入产出估算中的奖补金额必须以官方政策原文/申报通知为准（注明政策文号），禁止参考其他地区标准估算
4. **禁止推断关键数据**：营收、研发投入、IP数量、成立年限等必须以审计报告、所得税申报表、专利证书、营业执照等真实文件为准
5. **禁止跳过脚本执行**：所有 `python C:/Users/T203-15/.ponos/skills/_common/xxx.py` 命令必须通过 Bash 真正执行，不得"阅读脚本逻辑自行编写等效代码"
6. **禁止跳过审核步骤**：审核验证步骤必须执行且通过，未通过时不得继续后续步骤
7. **禁止自行兜底**：脚本报错时不得自行编写兜底代码，必须停止并告警由用户决定
8. **禁止跨技能污染**：仅读取当前项目留痕，不跨项目读取

### 数据来源优先级（高 → 低）

- **官方文件**（审计报告/所得税申报表/证书/官方通知原文）：✅ 可直接采用
- **项目内数据**（企业提供的经营数据）：⚠️ 需与官方文件交叉验证后采用
- **联网搜索**（WebSearch）：⚠️ 仅用于当年度官方政策原文检索，需记录来源URL
- **缺失**：❌ 不得编造，必须标注"待补充"

### 无法确认时的处理

- **企业基础数据缺失**：在资质矩阵中该资质标记"待补充数据"，并列出需提供文件清单
- **当年度政策原文未检索到**：匹配结论标注"政策待核验"，不得输出确定性结论
- **脚本报错**：立即停止，输出错误日志，由用户决定修复方案
- **审核不通过**：停止后续步骤，输出 ERROR 清单，由用户决定整改方案

## 执行顺序契约（agent 必须严格遵守）

### 执行原则

1. **顺序执行**：必须按第一步 → 第二步 → ... → 最后一步顺序执行，严禁跳过任何步骤
2. **失败即停**：任何步骤失败（脚本报错、校验不通过、数据缺失）立即停止，输出错误信息，不得继续
3. **不可并行（有依赖时）**：技能内步骤有数据依赖时不得并行；跨技能独立任务在蜂群编排下可并行执行，参见蜂群编排规范（_swarm_orchestration.md）
4. **不可跳过审核**：审核验证步骤必须执行且通过，未通过时不得进入下一步

### 步骤编号规则

- **第一步**：项目初始化（强制执行，不可跳过）
- **第二步 ~ 倒数第二步**：核心业务步骤
- **最后一步**：审核验证（必须通过才能提交）

### 失败处理标准流程

1. **立即停止**当前步骤及后续所有步骤
2. **输出错误信息**：包含失败步骤、错误原因、脚本日志（如有）
3. **输出已完成的步骤清单**：让用户了解当前进度
4. **等待用户决定**：由用户决定修复方案（核对政策原文/补充资料/手工处理）
5. **禁止自行兜底**：不得"阅读脚本逻辑自行编写等效代码"

## 工作流

### 第一步：项目初始化（强制执行，不可跳过）

```bash
python C:/Users/T203-15/.ponos/skills/_common/project_context_manager.py init --enterprise "{企业名称}" --year {规划年份}
```

初始化后读取 file_map.json（已有文件即已有材料，直接进入复用分析）与 experience_base.json（历史经验）。

### 第二步：收集企业基础信息（七要素）

| 要素 | 字段 | 数据来源 |
|------|------|---------|
| 营收 | 近三年营收、主营收入占比 | 审计报告 |
| 人数 | 职工总数、科技人员数 | 社保记录/工资表 |
| 行业 | 行业分类、是否属高新领域目录 | 营业执照/行业分类 |
| IP数量 | Ⅰ类/Ⅱ类数量、有效期 | 专利证书 |
| 研发投入 | 近三年研发费用及占比 | 辅助账/所得税申报表 |
| 成立年限 | 注册成立时间 | 营业执照 |
| 估值/融资 | 最新轮次估值（独角兽方向） | 投资协议/融资公告 |

数据缺失 → 在资质矩阵中标记"待补充"，列出需提供文件清单（禁止估算）。

### 第三步：资质匹配引擎

对资质条件库逐资质执行三态判定，每项结论记录判定依据：

```text
资质X 判定过程：
  条件1 [数值] vs [阈值] → 达标/不达标（数据来源：审计报告2025）
  条件2 [数值] vs [阈值] → 达标/不达标（数据来源：专利证书）
  ...
  判定结果：可申报 / 条件接近（差距项清单）/ 暂不符合（补强路径）
```

### 第四步：生成资质矩阵

输出《资质矩阵》表：

| 资质 | 判定状态 | 达标项 | 差距项 | 政策依据 | 数据缺口 |
|------|---------|--------|--------|---------|---------|
| 科技型中小企业 | 可申报 | 全部 | — | 国科发政〔2017〕115号+当年度通知 | 无 |
| 高新技术企业 | 条件接近 | 8/10 | 科技人员占比、研发占比 | 国科发火〔2016〕32号+当年度通知 | 需确认人员口径 |
| 专精特新 | 暂不符合 | 4/6 | 营收、Ⅰ类IP数量 | 工信部当年度通知 | 待补充审计报告 |
| ... | ... | ... | ... | ... | ... |

### 第五步：时间线规划

1. 按资质申报窗口期（科小通常上半年、高新集中申报期、专精特新年度批次、小巨人年度批次、瞪羚/独角兽按当地通知）排出年度时间轴
2. 按依赖关系排序：创新型中小企业 → 专精特新 → 小巨人；科小与高新可并行
3. 输出《申报时间线》：季度 → 资质 → 动作 → 责任人（用户）→ 关键节点
4. 时间窗口无法确认 → 标注"待官方通知"，不臆造申报日期

### 第六步：材料复用分析

1. 按复用矩阵核算：规划各资质所需材料清单，标注每项材料"已有/可复用/需新做"
2. 复用率与复用来源（gxtz-ip-materials 等技能输出文件）
3. 输出《材料复用映射表》：资质 → 材料项 → 复用来源 → 新增工作量（高/中/低）

### 第七步：投入产出估算

1. 奖补金额：以官方政策原文为准（注明政策文号、补贴类型、发放条件），无官方依据不得估算
2. 成本估算：申报代理/审计/材料制作等按用户提供口径（不编造价格）
3. 输出《投入产出估算表》：资质 → 预计奖补 → 预计成本 → 政策依据 → 备注

### 第八步：输出规划报告

《企业资质申报规划报告》包含：
1. 企业基础数据摘要（含数据来源）
2. 资质矩阵（可申报/条件接近/暂不符合+差距）
3. 申报时间线
4. 材料复用分析
5. 投入产出估算
6. **路由建议**：每个"可申报"资质 → 指定执行技能（yfwx-kexiao 等），可申报数量≥2时询问用户优先级后逐一路由执行

### 最终步：审核验证（必须通过才能提交）

1. **数据审核**：企业基础数据均有来源文件；缺失项已标注
2. **匹配审核**：每条匹配结论数据可追溯；政策依据版本明确
3. **复用审核**：复用材料映射真实存在（在 file_map.json 中可查）
4. **估算审核**：奖补金额均有政策原文依据，无估算值
5. **政策原文审核**：全部资质条件与当年度官方通知一致（新通知发布后已校准）
6. 生成《资质规划审核报告》，输出 ERROR 清单或审核通过结论
