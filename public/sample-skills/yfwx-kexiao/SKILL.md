## 合规红线（agent 执行前必读，违反即停止）

> **第一要求：严谨合规。所有资质数据必须来自官方政策原文，评分必须逐项可追溯，禁止编造任何申报条件。**

> ⚠️ **政策原文为准**：每年申报条件可能微调。本技能内置条件表为政策框架基准，**一切条件、分值、材料要求必须与当年度官方通知原文核对后采用**（评价系统/科技部门年度通知），并记录出处。

### 禁止事项（违反任何一条立即停止并告警）

1. **禁止编造申报条件**：职工人数、营收、资产、评分标准等条件不得凭记忆或推断填写，必须与当年度官方通知核对
2. **禁止编造评分结果**：自评打分每个得分项必须列明得分依据、数据来源与计算过程；无法取得数据的分项填"待补充"，不得估分
3. **禁止推断关键数据**：营收、研发费用、人员占比、科技成果等字段必须以审计报告、所得税申报表、专利证书、社保记录等官方文件为准
4. **禁止跳过脚本执行**：所有 `python C:/Users/T203-15/.yfworking/skills/_common/xxx.py` 命令必须通过 Bash 真正执行，不得"阅读脚本逻辑自行编写等效代码"
5. **禁止跳过审核步骤**：审核验证步骤必须执行且通过，未通过时不得继续后续步骤
6. **禁止自行兜底**：脚本报错时不得自行编写兜底代码，必须停止并告警由用户决定
7. **禁止跨技能污染**：仅读取当前项目留痕，不跨项目读取

### 数据来源优先级（高 → 低）

- **官方文件**（审计报告/所得税申报表/证书/官方通知原文）：✅ 可直接采用
- **项目内数据**（企业提供的经营数据）：⚠️ 需与官方文件交叉验证后采用
- **联网搜索**（WebSearch）：⚠️ 仅用于政策原文与官方通知，且需记录来源URL
- **缺失**：❌ 不得编造，必须标注"待补充"

### 无法确认时的处理

- **当年度官方通知未检索到**：停止申报流程，提示用户提供或协助检索官方原文，禁止用旧版条件直接替代
- **关键字段无法确认**：填写"待补充（需提供 xxx 文件）"
- **脚本报错**：立即停止，输出错误日志，由用户决定修复方案
- **审核不通过**：停止后续步骤，输出 ERROR 清单，由用户决定整改方案

## 执行顺序契约（agent 必须严格遵守）

### 执行原则

1. **顺序执行**：必须按第一步 → 第二步 → ... → 最后一步顺序执行，严禁跳过任何步骤
2. **失败即停**：任何步骤失败（脚本报错、校验不通过、数据缺失）立即停止，输出错误信息，不得继续
3. **不可并行（有依赖时）**：技能内步骤有数据依赖时不得并行；跨技能独立任务在蜂群编排下可并行执行，参见蜂群编排规范（_swarm_orchestration.md）

- **第一步**：项目初始化（强制执行，不可跳过）

3. **输出已完成的步骤清单**：让用户了解当前进度
4. **等待用户决定**：由用户决定修复方案（核对政策原文/补充资料/手工处理）
5. **禁止自行兜底**：不得"阅读脚本逻辑自行编写等效代码"

## 申报条件总览（政策框架基准，以当年度官方通知为准）

| 条件项 | 要求 | 数据来源 |
|--------|------|---------|
| 职工总数 | ≤500人 | 社保记录/工资表 |
| 年销售收入 | ≤2亿元 | 审计报告/所得税申报表 |
| 资产总额 | ≤2亿元 | 审计报告 |
| 评价得分 | ≥60分 | 自评打分表（见下） |
| 科技人员（20分） | 科技人员占职工总数比例 | 科技人员材料 |
| 研发投入（50分） | 研发费用总额/销售收入比例 | 辅助账/RD归集 |
| 科技成果（30分） | 知识产权数量与类型 | IP表/证书 |

**直通车条件（满足其一即直接符合，无需打分）**：
1. 拥有**有效期内**高新技术企业证书
2. 获得**国家级科技奖励**（近三年，前三完成单位）
3. 建有**省部级以上研发机构**（工程技术研究中心/企业技术中心等）
4. **主导制定**国际标准、国家标准或行业标准

## 工作流

### 第一步：项目初始化（强制执行，不可跳过）

```bash
python C:/Users/T203-15/.yfworking/skills/_common/project_context_manager.py init --enterprise "{企业名称}" --year {申报年份}
```

初始化后读取 file_map.json（文件分布）与 experience_base.json（历史经验）。

### 第二步：企业基础信息与硬指标核验

1. 从审计报告、所得税申报表提取：职工总数、年销售收入、资产总额
2. 与官方文件逐项比对，生成《硬指标核验表》（达标/不达标/待补充三态）
3. 任一硬指标不达标 → 暂停，告知用户不具备申报条件，建议转 yfwx-qualification-chain 评估其他资质

### 第三步：自评打分（可追溯）

按官方评分细则逐项打分，每项必须记录得分依据：

| 一级指标 | 满分 | 得分 | 得分依据（数据来源） |
|----------|------|------|---------------------|
| 科技人员 | 20 | ? | 人员材料+社保记录 |
| 研发投入 | 50 | ? | 辅助账+所得税申报表 |
| 科技成果 | 30 | ? | IP证书+获奖证明 |
| **合计** | **100** | ? | 必须≥60分 |

### 第四步：直通车条件检测

1. 检查是否持有有效期内高新证书（以证书有效期为准）
2. 检查是否获得国家级科技奖励（核对获奖证书，注明获奖年份与排名）
3. 检查省部级以上研发机构批文（核对批复文件）
4. 检查主导制定标准证明（核对标准发布公告，确认"主导"地位）
5. 任一满足 → 标注"直通车"，跳过评分门槛要求但仍需完成入库登记材料

### 第五步：入库登记材料准备

从高新材料中复用约80%材料（见"复用关系"），并补充科小专属材料：
- 知识产权汇总（复用 gxtz-ip-materials 输出）
- 科技人员汇总（复用 gxtz-staff-materials 输出）
- 研发费用归集（复用 gxtz-core-tables 的RD表）
- 直通车佐证（高新证书/奖励证书/研发机构批文/标准公告）

### 第六步：在线填报指引

1. 引导用户在官方评价系统（国家科技管理信息系统公共服务平台）完成注册与信息填报
2. 输出《填报字段映射表》：自评打分表 ↔ 系统字段对应关系
3. 填报完成后提醒用户核对系统生成的编号（科小编号）

### 第七步：年度更新提醒

- 科小资质**每年需重新评价**（通常上半年），设置下一年度更新提醒
- 输出《年度更新日历》：本年度申请时间窗口、材料复用清单、需更新数据

### 最终步：审核验证（必须通过才能提交）

1. **条件审核**：四项硬指标全部达标或直通车成立
2. **评分审核**：自评得分≥60分，每个得分项均有数据来源
3. **一致性审核**：复用材料与企业高新申报文件数据一致（营收/人数/IP编号）
4. **政策原文审核**：所有条件与当年度官方通知原文逐条核对一致
5. **文件审核**：调用命名规范检测（naming_compliance.py），PDF格式与大小合规
6. 生成《科技型中小企业申报审核报告》，输出 ERROR 清单或审核通过结论

## 与 gxtz-* 技能的复用关系（约80%材料复用）

| 所需材料 | 复用技能 | 复用方式 |
|----------|----------|---------|
| 知识产权证明材料 | gxtz-ip-materials | 证书/软著附件/专利状态材料直接复用 |
| 科技人员材料 | gxtz-staff-materials | 人员名单/比例说明/社保记录复用 |
| RD表/研发项目 | gxtz-core-tables、gxtz-rd-report | 研发项目汇总与立项报告复用 |
| 财务数据 | gxtz-core-tables（TOAI表） | 营收/研发费用数据复用 |
| 资料收集 | gxtz-info-collector | 复用资料收集流程与企微收集 |
| 文件打包 | gxtz-submission-packager | 复用打包流程 |
| 进度管理 | gxtz-progress-manager | 进度看板与依赖检查 |

**复用注意**：科小评价只做"评价"不做"认定"，材料以能支撑系统填报与佐证上传为准，无需全套高新申报文件；复用材料须按科小口径重新核对（如人员计算口径按评价细则）。
